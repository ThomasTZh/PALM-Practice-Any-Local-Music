# M3.10 plan — Manual rhythm, anchor, and meter editing

Spec: `projectPlans/milestone3.md` §12 (M3.10). Tenth Milestone 3 work
package. Adds transactional semantic commands for local grid repair,
idempotent receipts, revision conflicts, and persistent undo/redo.

**Acceptance (§12):** the user can repair a bad automatic grid locally
without destructive global quantization, and every correction survives
undo/redo and restart.

## Scope in / out

In:
- Domain command request/result union for pulse, downbeat, anchor, meter,
  bar origin/pickup, reinterpretation, and review state.
- `RhythmCommandService`: active-branch validation, project base revision,
  one pure edit, branch/project revision increments, before/after history,
  redo truncation, idempotency receipts, undo/redo, restart persistence.
- Locked-anchor behavior, explicit force override, linked pulse/anchor
  updates, grid-validity recomputation.
- Schema migration 15 for receipts/history and the rhythm history pointer.
- Unit tests and evidence.

Out:
- HTTP routes/409 JSON mapping (M3.17); service raises the conflict now.
- Editor lanes, selection, drag interactions, batch-review navigation
  (M3.11/M3.13).
- Unified project/rhythm undo stack and API shape (M3.17).
- Multi-region automatic meter sequence decoding (still deferred).

## Decisions

1. **One command per semantic correction.** A drag gesture maps to one
   command; no high-frequency command stream.
2. **Project revision is the concurrency guard.** Branch revision also
   increments and is checked optimistically; a stale project revision
   fails before any write.
3. **Separate rhythm history.** Existing project history cannot represent
   branch snapshots, so rhythm commands use their own before/after history
   and pointer. The UI must call the rhythm undo/redo for rhythm edits;
   unification is deferred.
4. **Receipts make retries safe.** The same idempotency key returns the
   stored result; a different command with the same key conflicts.
5. **Locks are explicit.** Automatic linked-anchor moves refuse a locked
   anchor; `force_locked` is the confirmed manual override.
6. **No destructive quantization.** Edits change only the selected pulse/
   anchor/region; neighboring timing is preserved.
7. **Review state is a command.** Accept/corrected state is transactional
   and undoable; navigation remains UI work.
