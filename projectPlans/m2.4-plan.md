# M2.4 plan — Prepare separation input consistently

Spec: `projectPlans/milestone2.md` §6. M2.3 pinned the bundled `htdemucs_ft`
baseline (44.1 kHz, stereo input, 4 output labels). This work package turns a
project's canonical PCM source into a deterministic, hash-identifiable,
model-ready prepared input plus a versioned global normalization profile.
No API (M2.17), no inference (M2.5).

## Resolved facts (2026-10-10, from the committed codebase)

**Existing building blocks (reused, not re-invented):**
- `media/derived.py::resample_playback` — versioned SWR resampler profile v1
  (`aresample=<target>:filter_size=64:exact_rational=1:dither_method=0`),
  returns `PlaybackOutcome` incl. `endpoint_difference_frames`
  (= actual − `round(src_frames × target/src)`).
- `media/derived.py::downmix_monitoring` — M1.7 stereo downmix via the
  precomputed pan matrix; source-rate stereo output.
- `media/downmix.py::resolve_downmix(channel_count, layout, l, r)` —
  `"standard_5_1"` for 6ch standard layouts, `"manual"` for user L/R
  selection, `None` for mono/stereo; `pan_expression(rows)` builds the filter.
- `media/decode.py::validate_pcm(path, channels) -> (sha256, max_amplitude)`
  — chunked frame-alignment/finiteness/hash/max-amplitude validation.
- Domain (M2.1): `SourceIdentity`, `ReferenceMixIdentity(asset_id, hash,
  transformation_hash)`, `SeparationRun.input_transform_hash`,
  `SeparationResultSet.reference_mix` — the prepared input feeds exactly
  these fields.
- Model requirement (M2.3 registry): `htdemucs_ft` — 44100 Hz, 2 channels
  (mono is duplicated for model input, spec §6.1).
- numpy is a main-env dependency; the main env stays torch/demucs-free.

**Demucs internal normalization (grounding for §6.3):** per-window
mean/std normalization of the magnitude spectrogram and the waveform with a
1e-5 epsilon (`htdemucs.py` forward). It runs per window, so window scales
vary with window content. The M2.4 global profile gives the M2.5 adapter a
whole-track reference scale so every window enters the model consistently;
demucs' internal step stays untouched (spec §6.3 rule 1: keep it separate).

## Design

### Domain — `src/basseparate/domain/preparation.py` (frozen pydantic)

- `DownmixSpec` — `mode: "standard_5_1" | "manual"`, `left_channel` /
  `right_channel` (required exactly for manual mode; forbidden for
  standard_5_1).
- `ReferenceMixPlan` — `kind: "stereo" | "mono" | "multichannel"`,
  `asset_id`, `source_hash`, `downmix: DownmixSpec | None`. Validators:
  multichannel requires a downmix spec; stereo/mono forbid one (§6.1 —
  multichannel separation is separation of the stereo downmix, and the UI
  must be able to say so from this record).
- `PreparedInput` — `asset_id`, `content_hash`, `transform_hash`,
  `sample_rate` (= model rate), `channel_count` (= 2), `frame_count`,
  `source_asset_id`, `source_hash`, `source_rate`, `source_frame_count`,
  `endpoint_difference_frames`, `time_mapping`, `created_at`. The
  `time_mapping` reuses the M1 `TimeMapping` (project_rate = source rate,
  representation_rate = model rate): the transform never trims, so the time
  origin is preserved and the mapping is the pure rate ratio (§6.2.8).
- `ChannelStats` — `mean: float`, `rms: float` (float64 values).
- `NormalizationProfile` — `version = "v1"`, `prepared_input_hash`,
  `frame_count`, `channel_count`, `max_abs`, `channel_mean: ChannelStats`,
  `full_channel: ChannelStats`, `mode: "normal" | "full_channel_fallback" |
  "exact_silence"`, `reference: "channel_mean" | "full_channel"`,
  `scale: float`, `epsilon: float`. Validators: finite stats;
  `scale == 0` iff `mode == "exact_silence"`; `epsilon > 0`.

### Service — `src/basseparate/media/preparation.py`

Constants (documented, versioned with the profile):
- `SEPARATION_INPUT_RECIPE = "separation-input-v1"`
- `NORMALIZATION_PROFILE_VERSION = "v1"`, `NORMALIZATION_EPSILON = 1e-4`
  (caps the pre-scale so near-zero references never yield unbounded model
  input, §6.4 rule 6), `FALLBACK_RATIO = 1e-2` (channel-mean variance vs
  full-channel variance threshold, §6.4 rule 3),
  `ENDPOINT_TOLERANCE_FRAMES = 2` (§6.2.9).

- `transform_identity_hash(plan, model_rate) -> Sha256Hash` — SHA-256 over
  the canonical JSON recipe: version, source hash, model rate, channel
  layout (2), downmix spec, resampler profile id, mono-duplication flag.
  Pure function → identical source + plan ⇒ identical transform identity
  (acceptance criterion).
- `compute_normalization_profile(pcm_path, sample_rate, channel_count) ->
  NormalizationProfile` — one streaming pass, float64 accumulators:
  - full-channel: Σx, Σx², max|x| over every sample of every channel;
  - channel-mean: per-frame mean m[t] = mean over channels, then Σm, Σm².
  - `rms_full = sqrt(Σx²/n)`, `rms_mean = sqrt(Σm²/n_frames)`,
    `var_mean = Σm²/n_frames − mean²`.
  - Mode: `max_abs == 0` → **exact_silence** (scale 0; the caller emits zero
    stems without inference, §6.4 rules 1–2); else
    `var_mean < FALLBACK_RATIO × var_full` → **full_channel_fallback**
    (anti-phase: the center is near zero, full-channel stats are the
    trusted reference, §6.4 rule 3); else **normal** (reference =
    channel-mean stats).
  - `scale = 1 / max(rms_ref, EPSILON)` (bounded, §6.4 rule 6).
- `async prepare_separation_input(*, source_path, source_rate,
  source_channels, source_hash, model_rate, downmix: DownmixSpec | None,
  work_dir, ...)` → `PreparedInputOutcome` (final path, content_hash,
  transform_hash, frame counts, endpoint difference, max_amplitude,
  profile, ffmpeg version, downmix mode). Pipeline (§6.2):
  1. pre-check: source file SHA-256 == `source_hash` (fail fast, §6.2.2);
  2. multichannel: `downmix_monitoring` (M1.7 matrix) → staging stereo at
     source rate;
  3. `resample_playback` (SWR profile v1) → staging at model rate;
  4. mono: duplicate to stereo with numpy (interleave; deterministic,
     byte-exact) — "duplicated only for model input" (§6.1);
  5. `validate_pcm` on the final file (alignment, finiteness, hash, max);
  6. duration: `|endpoint_difference_frames| ≤ ENDPOINT_TOLERANCE_FRAMES`
     (§6.2.9);
  7. `compute_normalization_profile` (via `asyncio.to_thread`);
  8. any failure removes all staging files (M1.7 cleanup rule).

The service is stateless; "store or reuse" (§6.2.6) is content-addressed
deduplication in the asset store — identical recipe + source bytes yield
identical prepared-input bytes and hash, so a second run reuses the existing
asset. Repository wiring is M2.5/M2.17 work.

### Tests

- Unit (`tests/unit/test_preparation.py`): domain validators; profile math
  on synthetic f32le files (exact silence → shortcut scale 0; DC; correlated
  stereo → normal; anti-phase sine → full_channel_fallback; near-silence →
  epsilon-capped scale; float64 accuracy vs a direct float64 computation;
  determinism); `transform_identity_hash` purity (same plan ⇒ same hash;
  different source/plan ⇒ different hash).
- Integration (`tests/integration/test_preparation.py`, real ffmpeg,
  M1.7 pattern): stereo 48 kHz → 44.1 kHz (frame count, endpoint diff,
  content hash); mono 44.1 kHz → stereo duplication (L == R byte-exact);
  5.1 downmix → 44.1 kHz; two runs byte-identical + same transform hash
  (acceptance); source hash mismatch rejected; duration tolerance.
