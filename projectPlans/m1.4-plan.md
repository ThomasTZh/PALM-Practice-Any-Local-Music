# M1.4 — Durable media jobs: implementation plan

Scope per `projectPlans/milestone1.md` §6. This builds the durable job
infrastructure. `probe` is the fully-executable reference job type; the other
four types (`canonical_decode`, `monitoring_downmix`, `playback_rate`,
`waveform`) are defined, schedulable, and durably tracked, but their execution
returns a structured `JOB_TYPE_NOT_IMPLEMENTED` failure (their real work lands
in M1.5–M1.7).

**Acceptance property:** a failed/cancelled job cannot corrupt a previously
completed asset.

## 1. Domain model — new `src/basseparate/domain/media_job.py`

- **`JobType`** (StrEnum): `probe`, `canonical_decode`, `monitoring_downmix`,
  `playback_rate`, `waveform`.
- **`JobState`** (StrEnum): `queued`, `running`, `completed`, `failed`,
  `cancelling`, `cancelled`, `interrupted`.
- **`JobStage`** (StrEnum, §6.6): `transferring`, `verifying`, `inspecting`,
  `decoding`, `preparing_playback`, `building_waveform`, `ready`.
- **`MediaJob`** (frozen Pydantic): `id`, `project_id`, `import_id?`,
  `job_type`, `state`, `stage?`, `progress_fraction?` (0–1, determinate only),
  `progress_detail?` (processed time/bytes for indeterminate), `result?`
  (per-type dict, e.g. ProbeResult), `error_code?`, `error?`, `max_threads`
  (default 4), `created_at`, `updated_at`.
- **Transition map** (enforced by the repository):
  - `queued → {running, cancelling, cancelled}`
  - `running → {completed, failed, cancelling, interrupted}`
  - `cancelling → {cancelled, interrupted}`
  - `interrupted → {queued, running, cancelling}` (restart from safe boundary)
  - `completed / failed / cancelled → {}` (terminal)
- Export from `domain/__init__.py`.

## 2. Worker protocol v2 — `src/basseparate/worker/protocol.py`

- Bump `WORKER_PROTOCOL_VERSION` → **2** in `basseparate/__init__.py`.
- New payloads + messages + builders:
  - `run`: `job_id`, `job_type`, `source_path`, `staging_dir` (validated abs
    paths), `max_threads`, `parameters` (dict).
  - `progress`: `job_id`, `stage`, `fraction?`, `detail?`.
  - `completed`: `job_id`, `result` (dict).
  - `failed`: `job_id`, `code`, `message`.
  - `cancel`: `job_id`.
  - `cancelled`: `job_id`, `staging_removed`.
- Add all six to the `WorkerMsg` discriminated union; update
  `worker/__init__.py` exports.
- **Explicit negotiation**: `hello` already carries `protocol_version`; add a
  supervisor helper `assert_protocol_version(hello)` that raises on mismatch.
  The worker already rejects non-matching per-message versions.
- New error code: `ERR_NOT_IMPLEMENTED = "JOB_TYPE_NOT_IMPLEMENTED"`.

## 3. Storage — migration 2→3 + `JobRepository`

- `db.py`: bump `DATABASE_SCHEMA_VERSION` → **3**; new `media_jobs` table
  (columns mirroring `MediaJob`, `CHECK` constraints on `job_type`/`state`,
  FK `project_id` CASCADE, `import_id` SET NULL) + indexes on `project_id`
  and `state`.
- `repository.py`: `JobRepository` using the existing per-op connection
  pattern:
  - `create_job`, `get_job`, `list_jobs_for_project`, `list_jobs_by_state`
  - `set_state` (validates the transition map; raises
    `InvalidJobTransitionError`)
  - `set_progress`, `set_result`, `set_error`
  - `mark_interrupted()` → flips `running`/`cancelling` → `interrupted`,
    returns count (called at startup).
- Export `JobRepository` from `storage/__init__.py`.

## 4. Media worker — new `src/basseparate/worker/media_worker.py`

A v2 worker. Concurrency model: the **main thread** reads stdin and handles
`describe`/`ping`/`cancel`/`shutdown`; a **job thread** runs the active job and
emits `progress`/`completed`/`failed`/`cancelled` to stdout (stdout writes
guarded by a lock). Only one job runs at a time (manager-enforced), so there
is at most one job thread.

- `run` dispatch by `job_type`:
  - `probe`: create staging dir → emit `progress(inspecting)` → run
    `probe_media(source_path, cancel_event=...)` → emit
    `completed(result=ProbeResult)` or `failed(mapped code)`. On cancel: kill
    the ffprobe subprocess, clean staging, emit `cancelled`.
  - other four types: emit
    `failed(JOB_TYPE_NOT_IMPLEMENTED, "implemented in a later milestone")`.
- `cancel`: set the shared cancel `threading.Event`; the in-flight probe
  observes it.
- `shutdown`: if a job is running, cancel it, join the job thread (bounded),
  then emit `stopped`.
- **`probe.py` change**: add optional `cancel_event` to `probe_media` + a
  `ProbeCancelledError`. On cancel: graceful `terminate()` → wait ≤5 s →
  `kill()` (satisfies §6.7).

## 5. Job manager — new `src/basseparate/jobs/` package

`JobManager` (async, lives in the API process, started in the app lifespan):
- Owns a `WorkerSupervisor` (worker command injectable for tests) + an
  `asyncio.Queue` of queued job IDs.
- `start()`: spawn worker → handshake → `assert_protocol_version` →
  `mark_interrupted()` → load `queued` jobs FIFO → start scheduler task.
- `stop()`: cancel scheduler task → stop supervisor.
- `create_job(project_id, import_id?, job_type, parameters?, max_threads=4)`:
  persist `queued`, enqueue.
- `cancel_job(job_id)`: terminal → no-op; `queued` → mark `cancelled`
  (scheduler skips it); `running` → mark `cancelling` + send `cancel`
  (scheduler finalizes on `cancelled`).
- `_scheduler_loop`: dequeue → skip if no longer `queued` → `_run_job`.
- `_run_job`: mkdir staging → `running` → send `run` → loop on `receive` (via
  `asyncio.to_thread`): `progress` → persist; `completed` → **verify**
  (reconstruct typed model) → `set_result` → `completed` → call optional
  `publisher`; `failed` → `set_error` → `failed` → clean staging; `cancelled`
  → `cancelled` → clean staging. Worker exit → `interrupted` + clean staging.
- `publisher` (injected, app-wired): for a `probe` job with an `import_id`,
  update the import's `probe_result` (+ auto-select single stream) — the
  "backend verifies and publishes" step.

## 6. API — `src/basseparate/api/job_routes.py` + errors

- `GET /api/v1/jobs/{job_id}` → `MediaJob`
- `GET /api/v1/projects/{project_id}/jobs` → list
- `POST /api/v1/projects/{project_id}/jobs` → `201 MediaJob` (body:
  `job_type`, `import_id?`, `parameters?`)
- `POST /api/v1/jobs/{job_id}/cancel` → `MediaJob`
- New `ApiError`s: `JobNotFoundError` (404), `InvalidJobType` (422).
- `app.py`: build `JobRepository` + `JobManager` in lifespan, wire the import
  publisher, start/stop, include `job_router`.

## 8. Contracts + verification + commit

Regenerate `contracts/openapi.json` + `frontend/src/api/schema.ts`, run the
full matrix (pytest, ruff check/format, mypy, typecheck, lint, vitest, build,
contract-drift), then a single **M1.4** commit + ledger update.

## Phasing

Implement in the order 1→8, running the relevant tests after each phase to
catch issues early, then the full matrix + one M1.4 commit. No frontend UI in
M1.4 (jobs have no user-visible surface until M1.5 decode exists); the job
API + generated schema are in place for it.

## Confirmed design points

1. `probe` stays inline in `complete_import` (M1.3, already verified) **and**
   is available as a worker job type — M1.4 does **not** rip out the inline
   probe.
2. The four non-probe job types fail with `JOB_TYPE_NOT_IMPLEMENTED` in M1.4
   (real execution deferred to M1.5+).
3. Single M1.4 commit at the end.
