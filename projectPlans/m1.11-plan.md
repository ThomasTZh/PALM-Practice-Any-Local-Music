# M1.11 — Navigation, zoom, and selection (plan)

Spec: `projectPlans/milestone1.md` §13. Frontend package: interactive
horizontal zoom, panning, selection semantics, vertical (amplitude) zoom
refinements, and the time-ruler position readout on the M1.10 editor.
AudioWorklet transport is M1.12; looping is out of scope.

## 1. Scope boundary

In M1.11:
- §13.1 Horizontal zoom: buttons, `+`/`-` keys, Ctrl/Cmd-wheel, pointer
  anchor, playhead anchor, Fit Song, Fit Selection, 8 px/frame max,
  boundary clamping, fractional coordinates.
- §13.2 Panning: scrollbar drag, Shift-wheel, overview-window drag,
  clamping, playhead-follow suspension, return-to-playhead button.
- §13.3 Vertical zoom: per-lane amplitude, linked scaling, reset,
  0.25×–16× range, persistence.
- §13.4 Selection: click/drag discrimination (3 px), click seeks, drag
  selects (no seek), frame boundaries, reverse-drag normalization,
  clamping, boundary handles, Escape clears, start/end/duration readout,
  "Seek to selection start."
- §13.5 Ruler: exact frame position readout at the pointer.

Not in M1.11: looping, marker editing (lane stays a display stub),
musical-analysis bars/beats, the AudioWorklet transport (M1.12), layout-
aware channel labels (5.1) — the M1.10 derived labels stay.

## 4. viewport.ts — interactive math (pure)

```ts
export const MAX_PX_PER_FRAME = 8
export const MIN_FPP = 1 / MAX_PX_PER_FRAME   // 0.125

/** Width-free view state: fractional start frame + zoom. */
export interface View { startFrame: number; fpp: number }

clampFpp(fpp): number                          // [MIN_FPP, +∞)
visibleFrames(view, widthCssPx): number        // width * fpp
clampView(view, durationFrames, widthCssPx): View
                                               // start in
                                               // [0, duration - visible]
zoomView(view, factor, anchorFrame, durationFrames, widthCssPx): View
                                               // fpp' = clampFpp(fpp*factor);
                                               // anchor frame stays at the
                                               // same x; then clampView
panView(view, deltaFrames, durationFrames, widthCssPx): View
fitRangeView(startFrame, endFrame, widthCssPx): View
                                               // fpp = width/(end-start);
                                               // if below MIN_FPP, clamp and
                                               // center the range
```

The component stores `View` (width-free); the full `Viewport` is derived
with `useMemo` so its identity changes only when start/fpp/width change.

## 5. engine.ts — minimal seek

`seek(offset)`:
- playing: stop all sources, `playStartOffset = scheduledUntil =
  clampedOffset`, new `playStartTime`, restart the scheduler loop.
- paused / stopped / idle: set `playStartOffset = scheduledUntil =
  clampedOffset` (stopped also clears `endReached`), report position.
- `currentOffset` in the `stopped` state returns `playStartOffset`
  (today: `endReached ? frameCount : 0` — equivalent, since `stop()`
  sets 0 and natural end sets `frameCount`).

Full seek-generation handling (flush acknowledgments, generation IDs)
is M1.12; this is the minimal seek the editor needs for click-to-seek
and "Seek to selection start."

## 6. useWaveform.ts rework

- Signature: `useWaveform(projectId, assetId, viewport: Viewport | null)`.
  The hook no longer derives the fit viewport; the component owns the
  view and passes the derived `Viewport` (null before it exists).
- Return drops `viewport`, gains `overview: WaveformLevelData | null` —
  the **coarsest** level's full tile set, fetched once per manifest and
  LRU-cached. This is the dedicated coarsest-level fetch the overview
  needs so the overview always shows the whole source, independent of
  the main view's zoom level.
- Decode moves to the `worker.ts` wrappers (`decodeTile`,
  `decodePcmPixels`, `decodePcmSamples`) — main-thread fallback in
  jsdom. Results are dropped when the owning effect is stale.
- The data-fetch effect key changes from `widthCssPx` to `viewport`, so
  every zoom/pan re-fetches the (adjacent-tile or PCM) range for the new
  window with the existing AbortController cancellation.

## 7. render.ts — new painters

- `drawSelection(ctx, x0, x1, height, opts)`: translucent fill of the
  range + a 3 px handle at each boundary (the hit target for
  §13.4.8).
- `drawOverviewWindow(ctx, x0, x1, height, opts)`: translucent window
  fill + 1 px border on the overview strip.

Both are pure, recorded by the stub context in tests.

## 8. WaveformEditor.tsx

### 8.1 State

- `view: View | null` — null until `manifest` + `contentWidth` are
  known; initialized to `fitViewport` once; kept (clamped) on width
  changes; replaced by zoom/pan/fit actions.
- `viewport` — `useMemo(makeViewport(view, contentWidth))`.
- `selection: { start: number; end: number } | null` — source frames,
  `end` exclusive, always `start < end`, clamped to `[0, duration]`.
- `followPlayhead: boolean` — default `true`.
- `scales: number[]` — per-lane amplitude, default `[1, …]`;
  `linked: boolean` — default `true`.
- `pointerFrame: number | null` — frame under the pointer (readout).
- `dragRef` — pointer interaction mode
  (`maybe` | `drag` | `resize-start` | `resize-end`).

New prop: `onSeek?: (projectFrame: number) => void`.

### 8.2 Horizontal zoom

- Controls fieldset "Horizontal zoom": **Zoom in** / **Zoom out**
  (×2 / ÷2, anchored at the viewport center; aria-labels
  "Zoom in (horizontal)" / "Zoom out (horizontal)" to stay
  distinguishable from the amplitude buttons), **Fit song**
  (`fitViewport`), **Fit selection** (disabled without a selection;
  `fitRangeView`).
- Keys on the editor section (`tabIndex={0}`): `+`/`=` and `-`/`_`
  zoom ×2/÷2 **anchored at the playhead** (§13.1.5).
- Ctrl/Cmd-wheel on the lane area: zoom by ×1.25/×0.8 anchored at the
  pointer (§13.1.4). Plain wheel is left to vertical lane scrolling.
  The listener is native + non-passive (React root wheel listeners are
  passive, so `preventDefault` must happen outside React).
- Every manual zoom/pan sets `followPlayhead = false`.

### 8.3 Panning

- **Shift-wheel** (lane area): pan by `(deltaX || deltaY) * fpp` frames.
- **Scrollbar**: the static bar becomes a track + draggable thumb.
  Thumb geometry from the view: `w = trackW * visible/duration`
  (min 24 px), `left = (start/duration) * (trackW - w)`. Pointer-down on
  the thumb drags; pointer-down on the track jumps + drags.
- **Overview window**: `drawOverviewWindow` indicator; pointer-drag on
  the overview canvas pans by `dx * duration/width`.
- **Follow**: while `followPlayhead` and a position update lands outside
  the visible range, pan so the playhead is visible again (only sets
  state when a change is needed — no 60 Hz render churn).
- **Return to playhead**: button shown while the playhead is outside
  the visible range; centers the view on the playhead and re-enables
  follow.

### 8.4 Selection (§13.4)

Pointer handlers on the lane area:
- `pointerdown`: hit-test selection handles first (±4 px of a boundary →
  `resize-start`/`resize-end`); otherwise `maybe` with the down x.
  Pointer-capture is attempted in a try/catch (jsdom no-op safety).
- `pointermove`: always updates `pointerFrame`; `maybe` + |dx| > 3 px →
  `drag` and create the selection; `drag` updates the range
  (normalized, clamped); `resize-*` moves one boundary (clamped, no
  crossing).
- `pointerup`: a `maybe` that never crossed 3 px is a **click** →
  `onSeek(round(xToFrame(x)))` clamped; drags select without seeking.
- `Escape` (section keydown) clears the selection.
- Selection layer: `drawSelection` on every shown lane; the readout row
  shows `start – end · duration` (via `formatTime`), a **Seek to
  selection start** button (`onSeek(selection.start)`), and a **Clear**
  button.

### 8.5 Vertical zoom (§13.3)

- `scales[]` per lane; when `linked` (default) the existing global
  buttons drive all lanes; "Link channels" checkbox unlinks → per-lane
  −/+ buttons appear in each lane's label cell and the global buttons
  disable. Reset restores 1× on all lanes and re-links.
- Persistence: `localStorage["basseparate:wave-amplitude:<projectId>"]`
  = `{ linked, scales }`, written on change, read (validated + clamped
  to 0.25×–16×) on mount; a length mismatch with the channel count
  resets to defaults.

### 8.6 Readout (§13.5.5)

A chip over the lane area (top-right, absolute) shows
`frame N · m:ss.mmm` for the pointer position while the pointer is over
the lanes. `drawRuler` already satisfies §13.5.1–4 and 6 (no changes).

### 8.7 App wiring

- `PlaybackPanel` gains `registerSeek?: (seek | null) => void`; an
  effect registers `(frame) => void engineRef.current?.seek(frame)` and
  deregisters on unmount.
- `ProjectView` holds `seekFn` state and passes it to the editor as
  `onSeek`. `WaveformEditor` re-renders on position ticks as today;
  `PlaybackPanel` stays memoized (stable props).

## 11. Risks / notes

- React 18 root wheel listeners are passive → the lane-area wheel
  handler must be attached natively with `{ passive: false }` to
  `preventDefault` Ctrl/Shift-wheel.
- jsdom: no `PointerEvent` constructor reliance — dispatch
  `new MouseEvent('pointerdown', …)` (type-based dispatch reaches
  React's `onPointerDown`); guard `setPointerCapture` in try/catch.
- 60 Hz playhead updates: follow logic must set state only when the
  view actually changes to avoid render loops.
- The overview fetch (coarsest level, full tile set) is small (a few
  tiles) and LRU-cached; it runs once per manifest.
- `seek` while `loading` is ignored (transient state).
- Fractional coordinates end-to-end: `View` keeps floats; only the
  readouts and the click-seek round.
