# M3.3 plan — Prepare rhythm-analysis input reproducibly

Spec: `projectPlans/milestone3.md` §5 (M3.3). Third Milestone 3 work
package. Produces the model-ready rhythm input representation and its
deterministic transform identity. No model inference, activation
publication, or job/API wiring.

**Acceptance (§5):** the same source and model profile produce a
reproducible analysis representation with an auditable source-time
mapping.

## Scope in / out

In:
- `RhythmInputPlan`/`RhythmInputProfile` domain records: input role,
  source identity, explicit downmix for multichannel sources, pinned
  Beat This! geometry, channel/amplitude transform, long-track strategy.
- `media/rhythm_input.py`: one continuous resample to 22,050 Hz using
  the versioned SWR profile; mono duplicated to stereo; explicit M1
  downmix for multichannel; endpoint validation; content hash; time
  mapping; deterministic transform identity.
- Tests for stereo/mono/multichannel, exact silence, very short audio,
  determinism, hash mismatch, misalignment, cancellation, and identity
  sensitivity.
- Evidence and ledger.

Out (later packages):
- Inference, activation arrays, run records (M3.4).
- Pulse decoding/tempo/meter (M3.5–M3.9).
- Durable job/API wiring (M3.17).
- Partial analysis intervals (not enabled yet, so the key excludes
  them).

## Decisions

1. **Prepared representation is 22,050 Hz stereo f32le.** The adapter's
   own documented transform is the mean over channels, so keeping the
   prepared audio stereo makes that the only channel reduction; mono
   sources are duplicated to stereo and reduce back exactly. Multichannel
   sources first use the explicit M1 stereo downmix (standard 5.1 or
   manual L/R), whose provenance is in the plan and the transform hash.
2. **No amplitude normalization.** Beat This! applies its pinned log-mel
   directly to raw samples; adding a pre-scale would diverge from the
   upstream implementation. The registry records this.
3. **One continuous whole-track resample**, not per-chunk resampling.
   The existing pinned SWR profile (`filter_size=64`, `exact_rational=1`,
   no dither) is reused.
4. **Long-track handling is upstream.** Beat This! `Spect2Frames` uses
   `split_predict_aggregate` (1500-frame chunks, 6-frame border,
   `keep_first`); no custom chunking is introduced. The profile records
   it in the cache identity.
5. **Source frames stay authoritative.** The outcome carries an exact
   `TimeMapping(project_rate, 22050)`; seconds are derived. Endpoint
   difference is recorded against the rounded conversion and must stay
   within the existing ±2-frame tolerance.
6. **Transform identity is content-based.** It covers source hash, role,
   downmix spec, model ID/manifest hash, adapter version, and the whole
   profile; it excludes the asset row ID so re-imported identical
   content reuses the same prepared representation.
7. **Degenerate audio is valid input.** Silence and very short audio
   prepare without error; no pulses later is a decoder outcome, not a
   preparation crash. No grid is fabricated here.
