# M1.13 plan — Buffering and browser compatibility

Spec: `projectPlans/milestone1.md` §15. Frontend-only. Extends the M1.12
AudioWorklet transport: moves fetch + deinterleave off the main thread into
a browser worker, adds the shared-memory path (cross-origin isolated) and
the transferable-buffer fallback, enforces the §15.3 buffer budget, adds
underrun diagnostics, and handles browser suspension and audio-device
changes. No backend changes.

Out of scope (later packages): synchronized readout refinements,
`getOutputTimestamp()` estimation, follow-playhead (M1.14).

## 2. Buffer budget (§15.3)

One shared 12 s retention budget per active representation:

- Network chunk: ~1 s (unchanged from M1.12).
- Initial prebuffer **and** post-underrun start threshold: 2 s.
- Steady lookahead: 8 s.
- Ring / SAB capacity: 12 s (`ceil(rate · 12)` frames) — the hard cap.
- Transfer path: the flow-control gate counts **ring + queue** against the
  12 s budget (send only while `ringCount + queued < budget − margin`,
  margin = 1 s chunk); a worklet `queue-high` notice is the safety net.
  Total retained PCM therefore stays ≤ 12 s (~4.6 MB stereo 48 kHz f32).
- Steady fill target: `min(8·rate, max(2·rate, frameCount − genStartFrame))`.
- Consumed history is retained in the ring (up to the budget); it is
  never used to advance audio, only retained.

## 3. Shared-memory path (§15.1)

- Availability: `mode: 'auto'` → `crossOriginIsolated &&
  typeof SharedArrayBuffer !== 'undefined'`; explicit `mode: 'shared'`
  forces it (tests).
- One SAB: 16-byte `Int32Array` header `[generation, writerIdx, readerIdx,
  0]` + interleaved f32 data region of `capacity · channelCount · 4`
  bytes.
- SPSC: the fetch worker is the sole writer — it copies the raw fetched
  (interleaved) bytes into the data region (wrap-aware, two copies at the
  seam) and then `Atomics.store` the new writer index. The worklet is the
  sole reader — `process` polls `Atomics.load` of the writer index (no
  blocking waits), consumes up to the block length, deinterleaves into the
  output channels, and stores the new reader index.
- Generation: the worklet ignores the ring until the header generation
  matches its local one (flushing → silence).
- **Index reset only after a flush acknowledgment**: on seek the transport
  posts `{seek, frame, generation}` to the worklet; the worklet resets its
  own reader index + local generation and posts `{flushed, generation}`;
  only then does the transport forward `{flush-ack, generation,
  baseFrame}` to the worker, which stores generation + writer index.
  In-flight worker fetches of the old generation are dropped.

## 4. Transferable-buffer fallback (§15.2)

- The worker fetches bounded ~1 s chunks, deinterleaves into per-channel
  `Float32Array`s, and posts them **transferred** to the main thread; the
  transport relays them to the worklet (`{chunks, channels, startFrame,
  frames, generation}` + transfer list).
- The worklet queues chunks (bounded by the §2 budget) and drains them
  into the ring at consumption time; `enqueue` overflow returns false and
  the chunk is dropped (flow control should make this unreachable; it is
  counted in diagnostics).
- Acknowledgments: the worklet posts `{consumed, frames, queuedFrames,
  generation}` (anchor cadence) and `{queue-high, generation}` when the
  budget is full; the transport pauses the worker on `queue-high` and
  resumes it when `queuedFrames` drops below `budget − margin`.
- Identical generation and EOF rules as the shared path: stale worker
  results and stale worklet chunks are dropped everywhere.
- The transfer path is exercised by tests even where shared memory exists
  (`mode: 'transfer'`), per §15.2.7.

## 5. Underrun behavior (§15.4)

Existing M1.12 behavior already covers detection, ramp-to-silence,
buffering state, frozen source advancement, and no skipped frames.
Additions:

- **Start threshold**: after an underrun, return to `playing` only when
  the worklet reports `bufferedFrames ≥ 2·rate` (initial start keeps the
  M1.12 "acknowledged render boundary" rule: any data).
- **Diagnostics**: the transport records underrun episodes
  (`diagnostics.underruns`, `lastUnderrunAt`) and dropped chunks; the
  panel shows a muted "Underruns: N" line when N > 0.

## 6. Browser suspension (§15.5)

- The transport subscribes to `context.onstatechange` (added to
  `TransportContextLike`).
- `suspended`: `isSuspended` true; the `position` getter stops
  extrapolating (last anchor only); `desiredPlaying` is preserved and the
  state machine is untouched (no state churn).
- `running`: `isSuspended` false; the fill loop re-engages if
  `desiredPlaying` and the state is active (context time was frozen, so
  the ring is intact — no refill gap).
- Resumption needs a user gesture where the browser requires one: `play()`
  (a gesture) awaits `context.resume()` when the context is suspended.
  The panel shows "Browser suspended audio — click Play to resume" while
  `isSuspended && desiredPlaying`.
- Tab visibility return: the panel's `visibilitychange` handler calls
  `transport.sync()` (report current state + position), so the UI
  redraws from actual transport state; there is no animation queue to
  replay.

## 7. Audio-device changes (§15.6)

- Detection: `onstatechange` → `state === 'closed'` (also checked on
  `play()` / `sync()`).
- On loss: the transport tears down graph + worker, **retains the last
  acknowledged position** (`retainedProjectFrame`), sets state `error`
  with `contextLost = true`.
- Recovery (the panel, on the error state with `contextLost`): create a
  fresh context (no gesture needed to *create*), re-read its actual
  `sampleRate`, re-resolve a compatible playback representation
  (`ensurePlaybackTarget`), `transport.rebind({target, projectRate,
  projectDurationFrames})` (resets to `unloaded`, keeps the retained
  position, seeks to it), then `transport.play()`.
- `rebind()` disposes the old graph/worker, stores the new source, resets
  to `unloaded`, and parks the playhead at `retainedProjectFrame`.
- Resumption follows the browser's gesture rules: if the fresh context
  starts suspended the suspension UI from §6 applies (Play resumes).

## 10. Risks / notes

- `SharedArrayBuffer` is available in Node 22 (tests for the shared path
  run in vitest); `crossOriginIsolated` is undefined there, so tests
  select the mode explicitly.
- jsdom has no `Worker`: the main-thread fallback (same `pcm-fetch.ts`
  code) is the default in tests; a fake worker covers the worker
  protocol. The Vite worker bundle follows the proven
  `waveform/worker-script.ts` pattern (module worker, importable
  helpers).
- The worker reads the Bearer token from `sessionStorage` (same-origin
  dedicated worker) via `getSessionToken`.
- SPSC safety: one index pair + generation; the worker is the sole
  writer, the worklet the sole reader; `Atomics.store` (writer) after the
  data copy and `Atomics.load` (reader) give the required ordering. No
  blocking waits on the audio thread.
- The relay hop (worker → main thread → worklet) on the transfer path is
  cheap: 1 s chunks, posted with transferred buffers.
- The 12 s budget gate counts ring + queue together, so total retained
  PCM never exceeds the §15.3 cap.
- Device-change *detection* here is context failure/closure (§15.6.1);
  proactive `navigator.mediaDevices` device-change events are not used in
  Milestone 1.
