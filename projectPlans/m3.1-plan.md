# M3.1 plan — Verify prerequisites and extend the domain

Spec: `projectPlans/milestone3.md` §3 (M3.1). First Milestone 3 work
package. Domain + schema + serialization + portable schema + contracts
only. No Beat This! runtime, no model download, no GPU, no network, no
analysis execution, no API routes for rhythm data.

**Acceptance (§3.11):** rhythm analysis, musical mapping, meter, and
practice settings can be represented without altering existing
source/stem timing.

## Scope in / out

In:
- Shared musical-position primitives (§3.2): exact reduced rational
  quarter-note position, meter/grouping/pulse/grid/lock/loop enums.
- Rhythm analysis run record (§3.3).
- Activation artifact metadata (§3.4); arrays stay outside JSON.
- Pulse, tempo-anchor, meter-region, bar-origin/pickup, and rhythm
  branch records (§3.5–§3.9).
- Project-level rhythm state (§3.10): active result/branch, Auto/Edited,
  lane/ruler visibility, snap mode, metronome and count-in settings.
- DB migration 12→13, project schema version 4→5, portable schema
  table list, regenerated contracts.
- Project serialization keeps all Milestone 0–2 data intact; old
  projects obtain default rhythm state.
- Tests: domain, invariants, repository round-trip, migration fixtures
  (empty/imported/separated/looped/portable), portable copy fixture.

Out (later M3 packages):
- Beat This! runtime/model registry (M3.2–M3.4), activation publication
  (M3.4), pulse decoding (M3.5), immutable automatic `RhythmResult`
  publication (M3.6; its table is added then), tempo-map/meter
  computation (M3.7–M3.9), editing commands/API/frontend (M3.10+),
  metronome/count-in audio (M3.14–M3.15), portable activation-file copy
  (M3.18).

## Fixed decisions for this package

1. **Musical position** is `MusicalPosition{numerator, denominator}`,
   reduced with the sign on the numerator, zero as `0/1`, denominator
   positive, normalized components within the JavaScript safe-integer
   range. Comparisons use exact cross-multiplication.
2. **Primary pulses are derived from `grouping`**, not stored twice.
   `MeterRegion.primary_pulse_starts` computes them by cumulative
   grouping sums. This keeps one authoritative grouping list (§3.7) and
   prevents divergence between "grouping" and "primary pulse".
3. **Display tempo unit** is an explicit `MeterTempoUnit` enum with a
   grouping-compatibility check: the unit's exact quarter-note length
   must equal either one denominator unit or one grouping part of the
   region.
4. **Branch storage:** the complete `RhythmBranchRecord` is persisted as
   `record_json` in `rhythm_branches` (the M2.1 result-set/stem pattern).
   Child records are embedded in that record; no per-pulse table exists
   yet. Editing commands in M3.10 update the branch record
   transactionally. Bounds (below) keep the JSON bounded.
5. **Automatic results are deferred to M3.6.** `active_result_id` and
   `parent_automatic_result_id` are nullable UUIDs without foreign keys
   until that package adds the table.
6. **Activation arrays** are immutable `.npy`-compatible files referenced
   by relative paths, validated for containment and `.npy` suffix. The
   manifest is a record; artifact files land in M3.4.
7. **Limits** (bounded JSON): 50,000 pulses, 10,000 tempo anchors, 1,000
   meter regions per branch; 64 grouping parts; 256 numerator/denominator
   bound; 128 warnings per run.
8. **Portable copy:** `rhythm_analysis_runs`, `rhythm_activation_artifacts`,
   and `rhythm_branches` are project-scoped and copied by the existence of
   their `project_id`; activation *files* are not copied until M3.18.
   The container version stays at 1 (no layout change).

### Known boundaries for this package

- Portable **open** does not yet import rhythm rows; save-side table
  copy is in place, and M3.18 wires rhythm contents into the archive
  read/remap path (Gate G). A M3.1 archive with rhythm rows would open
  without them.
- Portable archives written by earlier schema versions remain
  version-coupled: the embedded database must match the current schema
  version, so a v12 archive cannot be opened by this build. Resolving
  archive-schema upgrades belongs to M3.18.
- Automatic `RhythmResult` records and their table are M3.6; the branch
  parent and project active-result IDs are unconstrained nullable UUIDs
  until then.
