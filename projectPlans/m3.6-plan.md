# M3.6 plan — Publish immutable automatic rhythm results and branches

Spec: `projectPlans/milestone3.md` §8 (M3.6). Sixth Milestone 3 work
package. Completes the accepted/candidate → immutable result → editable
branch chain. Grid stages, editing commands, API, and UI remain later.

**Acceptance (§8):** automatic rhythm output is immutable, manual
corrections survive reruns, and every grid-dependent feature follows the
selected active rhythm version.

## Scope in / out

In:
- `domain/rhythm_result.py`: `RhythmResultRecord`, stage/status enums,
  deterministic result content hash, immutable-result validation.
- Schema migration 13→14: project-scoped `rhythm_results` table with run
  and activation references.
- Repository result operations (create/get/list/by run+stage) and the
  existing branch table.
- `rhythm/results.py`: decoded-stage publication with idempotent replay
  and conflict rejection, editable branch creation from a result,
  Auto/Edited activation through the project rhythm state.
- Rerun/preservation tests, migration and portable-copy updates, and a
  real end-to-end extension of the model integration test.

Out:
- Tempo-map/meter/complete result stages (M3.7–M3.9).
- Pulse/anchor/meter edit commands and undo/redo (M3.10).
- Rhythm APIs and UI result selector (M3.17).
- Portable open import of rhythm rows and archive schema upgrades
  (M3.18).

## Decisions

1. **One result per (run, decoded stage).** Verification status and stage
   are explicit; the decoded stage is not called `valid`. Later grid
   stages publish new records rather than mutating this one.
2. **Immutable result, mutable branch.** Branch pulses copy the result
   evidence with a new parent; the result rows never change.
3. **Progressive publication seam.** `stage`/`status`, `tempo_map_id`,
   `meter_result_id`, and `bar_origin_hypothesis` are present now so
   M3.7–M3.9 can attach grid evidence without a schema rewrite.
4. **Auto/Edited is project state.** Activation goes through
   `ProjectRepository.set_rhythm_state`, so it is revisioned and will
   join command/undo integration in M3.10.
5. **Result identity includes the run** (plus activation content, decoder
   profile, pulse evidence). Identical reruns therefore produce distinct
   results with stable per-result hashes; the decoded content hash
   remains the cross-run reproducibility identity.
6. **Branches start unmapped.** Without tempo anchors/meter regions a
   branch must not pretend to have a valid grid; M3.9/M3.10 fill it.
