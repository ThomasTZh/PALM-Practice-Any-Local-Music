## Phases

1. **Plan + ledger** — this file; ledger M2.3 section; current position.
2. **Provisioning (explicit developer step, §5.2.4)** — download the four
   checkpoints + yaml into the ignored `models/htdemucs_ft/` workspace dir;
   compute SHA-256; cross-check embedded checksums. *(done — facts above)*
3. **Manifest registry (§5.1)** — `src/basseparate/models/registry.py`:
   `ArtifactSpec` + `ModelManifest` frozen dataclasses, checked-in
   `REGISTRY` with the `htdemucs_ft` entry (real hashes/sizes/URLs/labels/
   notices), import-time invariants (unique names, no path traversal, 64-hex
   hashes, positive sizes, label order).
4. **Bundle service (§5.3, §5.4, §5.5)** — `src/basseparate/models/bundle.py`:
   `verify_bundle` → `bundled_available` / `bundled_missing` /
   `bundled_corrupt` (`BundleReport` carries per-artifact detail);
   `import_local_bundle` (strict manifest-defined file set, executable
   extension reject, copy, **verify-after-copy**, cleanup on failure);
   `ProvenanceStore` (JSON under the data dir, version 1, same pattern as
   `QualificationStore`); default model-dir resolution for the dev workspace.
   Diagnostics (`diagnostics.py`) gains a `model-baseline` check reporting
   the three states (optional capability — inference is not wired until
   M2.5, so it never blocks `doctor`).
5. **Offline qualification (§5.3.6)** — `analysis/qualify_bundled.py`:
   sets `HF_HUB_OFFLINE`/`TRANSFORMERS_OFFLINE` before importing demucs,
   re-verifies artifact hashes independently, loads from the explicit repo
   path, runs a 5 s inference; JSON report; evidence in
   `docs/evidence/m2.3-bundled-qualification.md` (git-ignored).
6. **Tests + full gate + commit** — registry structure tests, bundle
   verify/import state tests (fake artifacts in `tmp_path`), provenance
   store round-trip, diagnostics state tests; ruff, mypy, full pytest,
   contract drift check (no API change); `M2.3: ...` commit + ledger hash.

## Design notes

- Main env stays torch/demucs-free: verification is pure `hashlib`/`pathlib`.
  The no-remote-fallback *load* is exercised in the analysis env (Phase 5);
  the M2.5 adapter will call the same `get_model(name, repo=...)` form.
- `models/` (repo root) is git-ignored — the workspace dir holds the dev
  artifacts; the registry (checked in) is the source of truth for hashes.
- No config field for the model dir in this WP: the default is
  `<repo root>/models/<bundle_prefix>`; explicit directories are accepted by
  every service function, and a config/API surface is M2.17 work.
- Release packaging (§5.3.3–5.3.4) is served by `import_local_bundle`
  (copy + verify-after-copy + fail on mismatch); the packaging script itself
  is Milestone 7 work.
