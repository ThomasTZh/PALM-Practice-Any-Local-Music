# M1.7 — Monitoring channels and playback-rate representations: implementation plan

Scope per `projectPlans/milestone1.md` §9. Gate C covers M1.7.

**Acceptance property:** 44.1 kHz and 48 kHz sources play with correct pitch
and duration under either browser output rate.

## 0. Scope analysis — what earlier packages already delivered

- **§9.1 (part)** — canonical mono stays mono, stereo stays stereo (M1.5
  decode preserves the stream). Mono→speaker duplication happens in the
  browser (`AudioBuffer` with one channel is upmixed by the
  `AudioContext`); no disk copy is created.
- **§9.2.1** — all original channels are preserved in canonical storage
  (M1.5).
- **§9.6 (part)** — `TimeMapping` (project_rate / representation_rate) and
  `AudioRepresentation` with role `PLAYBACK_RATE` exist since M1.1; the
  `monitoring_asset_id` project column exists since the M1.1 schema.
- **`JobType.MONITORING_DOWNMIX` / `PLAYBACK_RATE`** — enum values exist
  (M1.4) and currently fail with `JOB_TYPE_NOT_IMPLEMENTED`.

Remaining gaps this work package closes:

1. **§9.2.2–9.2.5** — channel labels, stereo monitoring representation,
   recorded downmix matrix, monitoring mode visible in source info.
2. **§9.3** — explicit downmix rules: standard 5.1 matrix (row-normalized),
   unknown layouts → user selects L/R source channels, no guessing.
3. **§9.4** — browser sample-rate negotiation + "Preparing playback" +
   playback only from a complete representation.
4. **§9.5** — versioned SWR resampler profile; resample once, serve ranges.
5. **§9.6** — time-mapping readout, endpoint-difference recording, impulse
   tests.

## 1. FFmpeg research findings (8.1.2, verified)

- `pan` filter channel expressions accept only `coef*channel` terms joined
  by `+`/`-` — **no parentheses, no division**. Coefficients must be
  precomputed in Python.
- `|` in the pan spec is the filtergraph chain separator — it must be
  escaped as `\|` inside `-af`.
- 5.1 → stereo downmix verified spectrally with row-normalized
  coefficients: L = FL + 0.5·C + 0.5·Ls + 0.25·LFE, R mirrors with
  FR/Rs (after normalizing each row by the sum of absolute coefficients:
  L: 0.343147·c0 + 0.242639·c2 + 0.242639·c3 + 0.171574·c5).
- `aresample` options: `sample_rate`, `filter_size` (default 32),
  `exact_rational` (default true), `dither_method` (default 0 = none),
  `phase_shift`, `async` (default 0 = disabled). The playback profile pins
  all of them explicitly.
- Resampling 44100 ↔ 48000 maps integer-second inputs exactly (44100
  frames → 48000 frames, and back). A 480-frame impulse (44100) becomes
  523 frames (48000) with the peak at sample 0.
- ffprobe reports `5.1` and `7.1` for Matroska; WAV files carry the layout
  only when muxed with an explicit layout (`WAVE_FORMAT_EXTENSIBLE`).
  **The spec defines the standard matrix for 5.1 only** — 7.1 and every
  other layout fall into the "unknown layout" path (user selects L/R
  channels).
- Lossy codecs (opus) bleed energy across channels — channel-order and
  downmix verification must use lossless fixtures.

## 3. Downmix matrix — `src/basseparate/media/downmix.py` (new)

- `MATRIX_VERSION = 1`.
- `DownmixMode = Literal["standard_5_1", "manual"]`.
- `DownmixRow = tuple[tuple[int, float], ...]` (source channel, coefficient).
- `STANDARD_51_LAYOUTS = {"5.1"}`.
- Standard 5.1 rows (before normalization):
  L = [(0, 1.0), (2, 0.7071), (3, 0.7071), (5, 0.5)],
  R = [(1, 1.0), (2, 0.7071), (4, 0.7071), (5, 0.5)].
- `normalize_row(row)` — divides by the sum of absolute coefficients.
- `standard_51_matrix()` — normalized rows.
- `manual_matrix(left, right)` — L = [(left, 1.0)], R = [(right, 1.0)].
- `resolve_downmix(channel_count, channel_layout, left, right)` →
  `(mode, left_row, right_row) | None`:
  - `channel_count <= 2` → `None` (the canonical asset is the monitoring
    representation; §9.1).
  - `channel_count == 6` and `channel_layout == "5.1"` → standard.
  - otherwise → manual; `left`/`right` required (`MonitorSelectionError`
    when missing), each in `[0, channel_count)`.
- `pan_expression(left_row, right_row)` →
  `stereo\|c0=<terms>\|c1=<terms>` with 6-decimal coefficients
  (trailing zeros stripped); terms joined with `+` / `-`; `|` escaped.
- `channel_labels(channel_count, channel_layout)` →
  1: `["Mono"]`; 2: `["L", "R"]`; 6 + "5.1":
  `["FL", "FR", "C", "Ls", "Rs", "LFE"]`; otherwise
  `["Ch 0" … "Ch n-1"]` (never guess identities, §9.3).

## 4. Derived PCM engine — `src/basseparate/media/derived.py` (new)

Mirrors `decode.py`'s structure (asyncio subprocess, cancellation polling,
bounded stderr, progress events, no partial file on failure).

- `DerivedError` / `DerivedFailedError` / `DerivedTimeoutError` /
  `DerivedCancelledError` / `EmptyAudioError` / `NonFiniteSamplesError` /
  `InsufficientDiskSpaceError`.
- `RESAMPLER_PROFILE_VERSION = 1`;
  `PLAYBACK_RESAMPLE_FILTER =
  "aresample={rate}:filter_size=64:exact_rational=1:dither_method=0"`
  (no async — the default; float output makes dither moot, pinned for
  determinism).
- `DEFAULT_DERIVED_TIMEOUT_SECONDS = 1800.0`.
- Shared driver `_run_derived_ffmpeg(*, input_path, input_rate,
  input_channels, output_path, filter_expr, cancel_event, on_progress,
  timeout_seconds, max_threads)` →
  `(frame_count, content_hash, max_amplitude, byte_count)`:
  - input: `-f f32le -ar <rate> -ac <ch> -i <input>` (raw PCM in, no
    container).
  - output: `-c:a pcm_f32le -f f32le -progress pipe:2`.
  - validation reuses `check_frame_alignment` + `validate_pcm` from
    `decode.py`.
  - disk budget: `max(1.25 × expected output bytes, 64 MiB)` (no 2 GiB
    reserve — derived assets are bounded by the source size and deduped).
- `downmix_monitoring(*, source_path, output_path, sample_rate,
  channel_count, pan_spec, …)` → `DownmixOutcome` dataclass
  (frame_count, content_hash, max_amplitude, pcm_byte_count,
  ffmpeg_version).
- `resample_playback(*, source_path, output_path, source_rate,
  target_rate, channel_count, …)` → `PlaybackOutcome` dataclass
  (+ source_frame_count, expected_frame_count,
  endpoint_difference_frames).

## 7. Manager + app wiring

- `JobManager.create_job(…, parameters: dict)`; `_publish` verifies
  `MonitoringDownmixResult` / `PlaybackRateResult` before publishing.
- `app.py`: `_job_parameters_for(job, imports, projects, paths)` handles:
  - `canonical_decode` — as today.
  - `monitoring_downmix` — requires a ready project (canonical asset);
    `source_pcm_path` = canonical asset path; matrix from
    `resolve_downmix` (standard when 6ch + "5.1", else the project's
    stored L/R selection; `MISSING_MONITORING_SELECTION` failure when
    absent).
  - `playback_rate` — `target_sample_rate` from `job.parameters`
    (8 000–192 000); source = monitoring asset when present, else
    canonical; `INVALID_TARGET_RATE` / `NO_CANONICAL` failures.
  - Returns `{}` when a precondition is missing → the manager fails the
    job with the specific code.

## 9. API

- `POST /projects/{id}/jobs` — `CreateJobRequest.target_sample_rate:
  int | None` (8 000–192 000): required for `playback_rate`, rejected for
  other types (422).
- `PUT /projects/{id}/monitoring-channels` — `{left, right}`, project must
  be ready, `0 <= idx < source_channel_count` (422 otherwise). Returns the
  updated project.
- `GET /projects/{id}/source-info` — `{sample_rate, duration_frames,
  duration_seconds, channel_count, channel_layout, channel_labels,
  monitoring: {mode, asset_id, left_channel, right_channel} | null,
  playback_rates: [int, …]}`.
- `GET /projects/{id}/playback?rate=N` — resolves the asset to play:
  source = monitoring asset (when present) else canonical; same rate →
  that asset; else the `playback_rate` representation for (source, rate);
  404 `NO_PLAYBACK_REPRESENTATION` when none exists. Response:
  `{asset_id, role, sample_rate, channel_count, frame_count, byte_count,
  duration_seconds}`.
- `GET /assets/{asset_id}/bytes` — raw PCM with HTTP Range support
  (single byte range): 200 full, 206 partial with `Content-Range`,
  416 `RangeNotSatisfiable` with `Accept-Ranges: bytes`. Streamed in
  bounded chunks.

## 10. Frontend

- `contracts/openapi.json` + `frontend/src/api/schema.ts` regenerated.
- `src/api/playback.ts` — source-info, playback resolution, job creation
  (with `target_sample_rate`), job polling, monitoring-channel selection,
  ranged asset-byte fetch.
- `src/playback/pcm.ts` — pure: interleaved f32le `ArrayBuffer` →
  per-channel `Float32Array`; time-mapping helpers
  (`projectPosition(playbackFrame, projectRate, playbackRate)`,
  duration clamping to the canonical duration).
- `src/playback/engine.ts` — `PlaybackEngine`: owns the `AudioContext`
  (created/resumed on user gesture), chunked ranged fetch → `AudioBuffer`
  → back-to-back `AudioBufferSourceNode` scheduling with a lookahead;
  play/pause/stop; time readout in project frames; "preparing" state while
  a conversion job runs.
- `App.tsx` project view (ready projects):
  - source-info panel: rate, duration, channel labels, monitoring mode.
  - unknown-layout >2ch without a monitoring representation: L/R channel
    selects + "Create monitoring mix" button.
  - transport: Play (gesture) → AudioContext → resolve at context rate →
    404 ⇒ create `playback_rate` job + poll with "Preparing playback…" →
    fetch + play; Pause; Stop; time display; error display.
- Tests: vitest unit tests for `pcm.ts` (interleaving, offsets),
  `engine.ts` (state machine with a stub `AudioContext`), and the
  negotiation flow (reuse at equal rate, job path at different rate).

  and each of {44100, 48000} target rates: the resolved asset has the
  target rate, frame count = round(source_frames × target/source)
  (exact for integer seconds), duration within 1 sample of the source
  duration, and byte-identical content when target == source rate.
- **DB** — schema v4 migration from a v3 database (columns present,
  jobs/projects rows intact).
