# M2.6 plan — Validate and publish stems

Spec: `projectPlans/milestone2.md` §8. M2.5 leaves a **completed staged
run** in the analysis environment: four 44.1 kHz f32le stem PCMs plus a
`run-record.json` (frame counts, seeds, window policy, model identity,
effective parameters). This work package turns that into **published,
project-rate, validated stem assets and an immutable result set** —
including the "Bass + Others" residual and the reconstruction
diagnostics — with atomic result publication and representation
queueing. No API/job wiring (M2.17), no cache lookup (M2.7), no
frontend (M2.8).

## Resolved facts (codebase map, 2026-10-11)

- Domain `domain/separation.py` already models the target records:
  - `SeparationRun` (frozen): status lifecycle
    (`pending|running|completed|failed|cancelled|memory_fallback`),
    `result_set_id` required when completed, `ended_at` ⇒ `started_at`,
    `metrics: dict[str, float]`.
  - `SeparationResultSet`: `available_stem_roles`, `stem_ids`,
    `bass_residual_asset_id`, `reference_mix: ReferenceMixIdentity`,
    `reconstruction_metrics: dict[str,float]|None`,
    `validation_status`, `output_sample_rate/channel_count/frame_count`;
    validator: `valid` ⇒ ≥1 stem and frames > 0, no duplicate roles.
  - `StemRecord`: `role (vocals|drums|bass|other)`, channels/layout,
    frame count, `alignment_offset_frames` (± bound),
    `waveform_cache_asset_id`, `playback_representation_ids`,
    `confidence`, `provenance`.
- `domain/confidence.py`: `Confidence` with the strict
  `unavailable ⇔ value is None` rule — the spec §8.6 standard object.
  Use `Confidence(kind=unavailable)` for every stem.
- Assets are content-addressed (`data/assets/<sha256>.pcm`); M1 pattern:
  move the file into place, then register DB rows in one
  `BEGIN IMMEDIATE` transaction (`storage/repository.py::publish_source`,
  `jobs/publisher.py::_ensure_pcm_asset`).
- `SeparationRepository` (migration 6→7 tables, JSON-blob rows): create/
  get/list for run, result set, stems — **each insert is its own
  transaction; no run-status update, no multi-record publish** (gap).
- Media primitives to reuse: `media/decode.py::validate_pcm` (sha256 +
  max amplitude + non-finite rejection) and `check_frame_alignment`;
  `media/derived.py::resample_playback` (pinned SWR v1 profile,
  `PlaybackOutcome.endpoint_difference_frames`) and the M2.4 one-shot
  resample profile; `media/waveform.py::build_waveform_cache` +
  `WaveformCacheRepository.register(asset_id, result)` — the cache is
  keyed by asset content hash, so stem assets work unchanged.
- Jobs: `JobManager` + protocol v2; `JobType` CHECK =
  `probe|canonical_decode|monitoring_downmix|playback_rate|waveform`.
  Waveform jobs are auto-queued after canonical decode
  (`jobs/publisher.py::_queue_waveform_if_needed`) and published by
  `_publish_waveform`, which **requires the project's canonical asset**;
  `app._waveform_parameters_for` always resolves the canonical asset —
  reuse for stems requires generalizing both. Playback-rate jobs are
  **on-demand** (`api/playback_routes.py`), not eagerly queued (M1
  semantics); stems follow the same on-demand policy once exposed
  (M2.17).
- Reference mix: resolve through the M2.4 `ReferenceMixPlan`
  (stereo as-is / mono duplicated / explicit downmix) at **project**
  sample rate; the project's `sample_rate`/`duration_frames`/
  `channel_count` are the restore targets.
- Services style (M2.2–M2.5): stateless async functions in `media/*.py`,
  dataclass outcomes, typed exceptions, caller-supplied work dir,
  bounded chunks, `on_progress`/`cancel_event`, tests in
  `tests/unit`/`tests/integration` with `tests/synth.py` PCM fixtures.

## Design

### Domain + repository (main env)

- `StemRole` gains `OTHERS = "others"` — a **publication** role for the
  §8.4 residual, distinct from the model's `other` (the registry keeps
  its four model roles). Validators: at most one `others` per result
  set; when present, `bass_residual_asset_id` must reference its asset.
- `SeparationRepository.publish_result_set(...)`: one
  `BEGIN IMMEDIATE` transaction inserting the hash-idempotent asset rows
  + `project_assets` stem linkage, the `SeparationResultSet` row (before
  the stems — the stems table has an FK to the result set), the
  `StemRecord`s and the run completion (`status=completed`,
  `result_set_id`, `ended_at`), mirroring `publish_source` (rollback
  leaves nothing; an already-published run is rejected). No base
  representation rows: the asset `AudioMetadata` carries
  rate/channels/frames. **Implemented (Phase 2).**
- `SeparationResultSet.reconstruction_metrics` keys (documented):
  `reconstruction_rms`, `reconstruction_max` (four stems vs reference
  mix) and, for Bass + Others, `residual_reconstruction_max`.

### Media services — `src/basseparate/media/publication.py` (new)

1. `restore_stem_project_representation(...)` — staged 44.1 kHz f32le →
   project rate using the pinned continuous resampler (identity fast
   path when rates match; no whole-file buffers beyond chunk size);
   stereo projects keep stereo; mono projects collapse with the
   documented average `(L + R) / 2` (float64 intermediate, float32
   output). Endpoint policy: permit only the documented resampler
   endpoint rounding (±2 frames, M2.4 convention); output must match
   `project.duration_frames` exactly; anything larger is a failure, never
   a blind trim (§8.1.8–9).
2. `validate_stems(...)` — the §8.2 checklist: roles complete and unique
   (from labels), frame count = canonical project frames, channels,
   sample rate, finite samples (`validate_pcm`), sha256 content identity,
   no missing output, `max_amplitude` recorded. The no-clip /
   no-normalization property is enforced structurally (all restore
   transforms are unit-gain and linear — unit tests assert bit-exact
   identity when the project rate already matches) and monitored by the
   reconstruction diagnostics.
3. `compute_reconstruction_error(reference_mix, stems)` — bounded
   chunks, float64 intermediate; returns `(rms, max)` for
   `reference_mix − Σ four_stems` (§8.3). Raw four-stem output is not
   claimed exact.
4. `derive_bass_residual(reference_mix, bass)` — `others =
   reference_mix − bass` in bounded float64 chunks, stored as float32
   PCM (§8.4); verification `reference_mix − (bass + others)` within
   float32 rounding tolerance; labeled "Others", provenance
   `{"kind": "bass_residual", "formula": "reference_mix - bass"}`.
5. `publish_separation_result(...)` — orchestrates: read + validate the
   staged run record and stems, restore project representation,
   re-validate, compute diagnostics, derive the residual when
   `requested_mode == bass_pair` (the four model stems are always
   published and retained; §8.5), move assets into the store, then the
   transactional repository publish. Staging cleanup only on success.

### Representation queueing

- Generalize the waveform path for arbitrary source assets: WAVEFORM job
  parameters carry the source `asset_id`/content hash (fallback to
  canonical for existing jobs); `_publish_waveform` attaches the cache
  to that asset; `_queue_waveform_if_needed` gains a per-asset variant.
  After publication, queue one waveform build per published stem —
  publication is atomic and complete first, so audio is available while
  optional waveform preparation continues (§8.7.5–6).
- Playback-rate representations stay **on-demand** (the M1 policy for
  the canonical asset too): the published stems are ordinary assets with
  time mappings, so the existing playback path serves them once the API
  exposes stem groups (M2.17); eager per-stem conversion has no known
  target rate at publication time. Documented in the ledger.

### Staging

- Separation runs stage under `runtime/separation/<run_id>/attempt-N/…`
  (not `runtime/jobs/*`, which `JobManager` wipes at startup); the
  publish service takes the staging directory explicitly, so tests use
  temp dirs and M2.17 only decides the location.

## Phases

1. **Plan + ledger** — this file; ledger M2.6 section.
2. **Domain + repository:** `StemRole.OTHERS`, result-set validators,
   `publish_result_set` transaction + run completion; unit tests for the
   validators, integration tests for atomicity/rollback/idempotency.
3. **Media services:** restore / validate / reconstruction / residual
   with synthetic PCM fixtures; unit tests (identity rate path, mono
   average, endpoint tolerance, chunk bounds, non-finite rejection) and
   integration tests with the real resampler.
4. **Publication + queueing:** `publish_separation_result` end-to-end on
   a synthetic staged run (no GPU); waveform queueing generalization and
   publisher checks; integration tests incl. failure paths leaving no
   partial records.
5. **Evidence + close:** full gates (pytest/ruff/mypy/contract), ledger,
   commit + ledger hash follow-up.
