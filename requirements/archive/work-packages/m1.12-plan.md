# M1.12 plan — AudioWorklet transport

Spec: `projectPlans/milestone1.md` §14. Frontend-only. Replaces the
`AudioBufferSourceNode` scheduling engine (M1.7, `engine.ts`) with an
AudioWorklet-based transport. No backend changes.

Out of scope (later packages): shared-memory ring (M1.13 §15.1), refined
buffer defaults (M1.13 §15.3), browser suspension / device-change recovery
(M1.13 §15.5–6), synchronized-readout refinements (M1.14).

## 2. Worklet core (`worklet-processor.js`)

Plain JS (no TS, no imports) so the same file works as a Blob-URL worklet
module and as a Vitest import (tests stub `AudioWorkletProcessor` /
`registerProcessor` globals before importing).

`export class ConsumptionState`:

- Constructor: `{ sampleRate, channelCount, frameCount, anchorEveryFrames = 480 }`
  (480 = 10 ms at 48 kHz). Fixed per-channel ring capacity
  `ceil(sampleRate * 8)` frames (bounded allocation; 8 s ≫ 2 s prebuffer).
- `position` — next frame to consume (playback frames).
- `enqueue(buffer: ArrayBuffer)` — deinterleave f32le into the ring;
  returns `false` (caller drops the chunk) if it would overflow the ring.
- `seek(frame)` — clear the ring, `position = frame`, `flushing = false`,
  cancel any pause ramp. This is the stale-audio barrier: nothing
  enqueued before the seek can be output after it.
- `pause()` — begin a ~5 ms (ceil(0.005·rate) frame) output ramp: the last
  consumed samples are held and scaled down without advancing `position`,
  then silence. Consumption stops; the acknowledged position is preserved.
- `resume()` — end the ramp; consumption continues exactly at `position`.
- `process(time, outputChannels)` — `frames = outputChannels[0].length`
  (**actual block length**, spec §14 intro). Fills every channel
  deterministically:
  - paused/ramping → ramped hold samples, then silence;
  - `flushing` or ring empty → silence; `underrun = true` only if data was
    expected (i.e. not within one block of a seek/pause);
  - else consume up to `frames` samples, remainder silence.
  - When `position` reaches `frameCount`: `ended = true`, final anchor.
  - Emits an anchor `{ frame, time }` whenever `position - lastAnchorFrame
    >= anchorEveryFrames`, plus exact anchors on pause/seek/end. The
    anchor's `frame` is the position *before* this block's consumption and
    `time` is the block start context time, so main-thread extrapolation
    is `anchorFrame + (ctx.currentTime - anchorTime) · rate`.
- Returns `{ consumed, underrun, ended, anchor: {frame, time} | null }`.

`registerProcessor('basseparate-pcm', PcmProcessor)` (guarded by
`typeof AudioWorkletProcessor !== 'undefined'`): the adapter owns the
`ConsumptionState` (created in the constructor from
`options.sampleRate / channelCount / frameCount`), handles port messages
(`{samples, buffer}` → `enqueue` + transfer, `{seek, frame, generation}`,
`{pause}`, `{resume}`, `{dispose}`), replies (`{flushed, generation}`,
`{anchor, frame, time, generation}`, `{underrun, generation}`,
`{ended, generation}`), and calls `core.process(time, output)` in
`process(time, input, output, parameters)`. No network, no promises, no
logging, no unbounded allocation in `process` (§14.7).

## 3. Transport (`transport.ts`)

`PcmTransport` with injectable `contextFactory`, `fetchChunk`, `delay`
(all defaulted), mirroring the engine's testability pattern.

- **States (§14.3):** `unloaded | preparing | paused | playing | seeking |
  buffering | ended | error`, plus internal `desiredPlaying` (kept separate
  so seeks/underruns pause output without losing user intent).
- **`loadSource(target, projectRate, projectDurationFrames, opts)`** —
  `preparing`: create/resume context (if owned, `ownsContext`),
  `audioWorklet.addModule(blobUrl)` (Blob from the `?raw` import),
  `createWorkletNode('basseparate-pcm', {processorOptions: {...}})` →
  `createGain()` → `destination`. Then start the prefetch fill.
- **Prefetch:** while `desiredPlaying` and state is `preparing | playing |
  buffering | seeking`: fetch ~1 s chunks (`rate · 4 · channelCount`
  bytes, clamped to file end) with one shared `AbortController` per
  generation; post `{samples, buffer}` (transfer) to the worklet; track
  `fetchedFrame`. Target = `max(2·rate, frameCount - startFrame)` frames
  ahead of the estimated consumed position. First fill reaches the
  worklet before state leaves `preparing` → "start on an acknowledged
  render boundary" (§14.4.5–6: the worklet outputs silence until data
  arrives, so the first audible block is exactly at `position`).
- **Position:** on `{anchor}` → `lastAnchor = {frame, time}`; reported
  position (project frames) = `projectPosition(anchorFrame +
  (ctx.currentTime - anchorTime) · rate, rate, projectRate)` clamped to
  `projectDurationFrames`, reported on each anchor (~10 Hz) and on
  state changes.
- **`play()`** (§14.4): from `paused`/`ended`/`unloaded`; sets
  `desiredPlaying`, `resume()` message (or initial fill), state
  `playing` once the fill is acknowledged by the worklet having data.
- **`pause()`** (§14.5): `{pause}` message, state `paused`, position
  frozen at the acknowledged anchor.
- **`stop()`** (§14.5): pause semantics + `seek(0)` + generation bump;
  ring data is re-fetched on next play (cached chunk data is discarded —
  the spec's "keep reusable cached data" is satisfied by the tile/PCM
  HTTP cache at a later layer; for M1.12 the transport re-fetches).
- **`seek(projectFrame)`** (§14.6): convert via `playbackPosition`, bump
  `generation`, `{seek, frame, generation}` to the worklet, abort the
  in-flight generation's fetches, reset `fetchedFrame = frame`; if
  `desiredPlaying` → state `seeking` until the fill completes → `playing`;
  if not playing → position-only (state `paused`/`unloaded` preserved;
  this is the M1.11 click-to-seek behavior). Late messages/fetches from
  older generations are dropped everywhere (generation checks on every
  port message and fetch settlement).
- **`setOutputGain(g)`** (§14.8): clamp `[0, 4]`,
  `gain.gain.setTargetAtTime(g, ctx.currentTime, 0.01)`; canonical samples
  are untouched (gain sits after the worklet). Default 1.
- **`dispose()`**: `{dispose}` message, disconnect node, close the context
  if owned, revoke the Blob URL.
- **Underrun:** on `{underrun}` while `desiredPlaying` → state
  `buffering`; the prefetch loop refills; the worklet emits silence (no
  time skip — §15.4.8's "never skip unplayed frames" is inherent:
  `position` only advances on consumption).
- **End:** on `{ended}` → state `ended`, report final position.

## 4. App integration (`App.tsx`, `styles.css`)

- `PlaybackPanel`: swap `PlaybackEngine` → `PcmTransport`; `seekFn` calls
  `transport.seek(frame)` (project frames); `onState` / `onPosition`
  wiring unchanged.
- Button labels: `playing` → Pause; `paused | ended | unloaded` → Play;
  Stop disabled while `unloaded`; `preparing | seeking | buffering` →
  disabled + "Preparing playback…" status line; `error` → alert line.
- **Monitoring volume** (§14.8.1, .5): range input 0–200 % (step 5),
  default 100 %, `aria-label="Monitoring volume"`, drives
  `setOutputGain(v / 100)`; a "may clip" hint shows above 100 %.
- `.playback-volume` styles in `styles.css`.

## 5. Test matrix

`worklet-core.test.ts` (import the .js module; stub
`AudioWorkletProcessor` + `registerProcessor` globals):

1. `process` uses the actual block length: 128-, 192-, and 186-frame
   blocks all fill exactly and consume the right samples.
2. Enqueued samples come out in order, stereo, f32.
3. Underrun → silence + `underrun` flag; no flag right after a seek.
4. Pause → ~5 ms ramp (decreasing, nonzero) then silence; `position`
   unchanged; resume → exact continuation (no sample drift across
   pause/resume).
5. Seek clears the ring: stale enqueued data is never output after a
   seek (the stale-audio acceptance).
6. End: after `frameCount` frames, `ended` + silence + final anchor.
7. Anchors: emitted every `anchorEveryFrames` with the correct
   `{frame, time}`; exact anchors on pause/seek/end.
8. Ring overflow → `enqueue` returns false (bounded).

`transport.test.ts` (fake context: `addModule` resolves,
`createWorkletNode` returns a fake node whose `port` the test drives;
`createGain` records `setTargetAtTime`; mutable `currentTime`;
`fetchChunk` mock; `delay` resolves immediately):

9. `loadSource` + `play`: addModule once, node created, chunks fetched
   with correct byte ranges, `preparing` → `playing` after the 2 s fill.
10. Pause: `{pause}` posted, state `paused`, reported position frozen.
11. Stop: position 0, generation bumped, in-flight fetch aborted.
12. Seek while playing: `{seek, generation}` posted, old fetch aborted,
    refetch starts at the new position, `seeking` → `playing`; an anchor
    from the old generation is ignored (position never rewinds).
13. Seek while unloaded: position-only park (M1.11 behavior), no context
    created.
14. `{ended}` → state `ended`, position = duration.
15. `{underrun}` → `buffering`; refill posts samples; → `playing`.
16. `setOutputGain` → `setTargetAtTime(g, now, 0.01)`; clamp at 4.
17. `dispose` → node disconnected, owned context closed.

## 7. Risks / notes

- The worklet file is plain JS: `tsc -b` ignores it (no `checkJs`);
  `?raw` import is a string; Vitest imports it as an ES module with the
  globals stubbed. eslint must accept the `.js` file (verify; add an
  override only if needed).
- Blob-URL `addModule` works in Chrome/Firefox/Safari; revoke on dispose.
- Anchor cadence 480 frames (10 ms) → ~100 small messages/s: fine.
- Rate conversion: playback representation may differ from the project
  rate; all anchors are playback frames, converted at the transport
  boundary only (editor playhead stays in project frames, as in M1.11).
- The 2 s prebuffer + 1 s chunk is the M1.12 baseline; M1.13 tunes
  defaults and adds the shared-memory path.
