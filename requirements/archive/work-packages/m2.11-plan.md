## Design

### Stream model (the core idea)

A loop turns the transport's data stream into a **periodic stream**
over `[start, end)`: after `end` the stream continues at `start`. The
transport and the worklet both track a **stream coordinate** `c`; the
source frame it carries is

    sourceOfStream(c) = loop ? start + ((c - start) mod len) : c

Stream coordinates are **source-aligned at each seek boundary**: a seek
to source `B` makes the audible boundary the stream coordinate `B`
(`genStartFrame = B`), so `sourceOfStream(B) = B` for any `B` inside
the loop. After wraps the coordinates drift by multiples of `len`; the
mod mapping absorbs that. No worklet-side wrapping is needed: the
transport feeds the periodic content in stream order and the worklet
reads it linearly.

- **Fetch cycling** (transport): each fetch chunk is clamped to the
  next pass end in source space —
  `frames = min(chunkFrames, loopEnd - sourceOfStream(cursor))` — so
  the source ranges never cross a wrap; the byte range is always
  contiguous. After the chunk the cursor advances in stream space.
- **Pre-roll** (§13.7.2/§13.7.4): a loop seek fetches
  `fetchFrame = B - PRE_ROLL_FRAMES` **without the `max(0, …)` clamp**
  when the loop is active — a negative stream coordinate is legal and
  maps (via the mod formula) to the loop's tail. Short loops
  (< 12 288 frames) wrap through the pre-roll several times; the ring
  content stays the correct periodic stream. The shared ring's
  writer/reader modulo becomes negative-safe.
- **Position** (transport): the ledger stays in stream coordinates
  (monotonic — no wrap handling in extrapolation); the public
  `position` maps stream → source with the mod formula, then to
  project frames. The worklet's anchors stay exact `(frame, time)`
  pairs, now naming stream positions.
- **Worklet loop spec**:
  `{start, end, repeatCount: number | null, fade: boolean}`; the pass
  ends are the stream coordinates
  `E_k = current + (end - sourceOfStream(current)) + k·len`
  (the first pass is partial when enabled mid-loop, §13.4.3).
- **Wrap anchors**: at each pass crossing the worklet emits an exact
  anchor `{frame: E_k, time: crossingTime, rate}` — the UI snaps
  precisely at wraps and the §13 acceptance test measures the
  crossings.
- **Cumulative fractional accounting** (§13.7.5–6): the wrap is defined
  by the stream crossing (`audible` is a float advanced by `rate ×
  frames`); per-iteration durations are never rounded. At a constant
  rate the output spacing is exactly `len / rate` output frames with
  the fractional remainder carried in the stream position.

### Boundary fades (§13.6)

- Output-domain envelope at each pass crossing: fade out over the last
  `fadeFrames` before `E_k`, fade in over the first `fadeFrames` after.
  `fadeFrames = min(round(5 ms · sampleRate), round(len / rate / 4))`
  (§13.6.2), applied to the mixed dry/wet output before the master
  gain. `fade: false` skips it (exact boundary audition, §13.6.5) and
  keeps the 1× dry path bit-exact.
- The stored audio is untouched (§13.6.6); the loop duration is
  preserved — the fades attenuate, they do not overlap or shorten
  (§13.6.3–4).

### Playback behavior (§13.4)

Transport rules (all applied on the SOURCE-mapped position):

1. `setLoopEnabled(true)` while not playing: state only; no transport
   action (§13.4.1).
2. `play()` with the loop enabled and the position outside
   `[start, end)` (including the completion state `position == end`):
   synchronized seek to `start` first (§13.4.2, §13.4.7).
3. `setLoopEnabled(true)` while playing inside: send `{type:'loop'}`
   to the worklet; playback continues from the current position
   (§13.4.3).
4. `setLoopEnabled(true)` while playing outside: synchronized seek to
   `start` (§13.4.4).
5. `seek(B)` with the loop enabled and `B` outside: looping is
   disabled (`loop_enabled = false` via the `onLoopDisabled` callback —
   the App persists it) and the saved loop is retained (§13.4.5).
6. Finite repeats: the worklet counts passes; when the last pass ends
   it stops exactly at `E` (the position clamps to `loopEnd`, the
   fade-out plays) and emits `loop-complete`; the transport goes
   `paused` at `loopEnd` (§13.4.6). `repeat_count` = **total passes**
   (a partial first pass counts as pass 1).
7. `setLoop(spec)` / `setLoopEnabled(false)` while playing: a
   controlled transition (§13.8) — synchronized re-seek to the current
   source position (inside the new range) or to the new `start`
   (outside), with the new spec. Boundary edits are committed by the
   UI on drag end, so a drag is one transition.
8. `setLoop(null)`: same controlled transition with `loop: null`.

### Buffering (§13.5)

- The pre-roll + initial pass are pinned by the existing flow-control
  budget (the fetch cursor cycles, so the upcoming pass is always
  fetched ahead of the worklet); the byte budget (`budgetFrames`,
  12 s) is unchanged and measured in stream frames.
- No fetch on the audio thread (unchanged); a starved loop takes the
  existing underrun → `buffering` path and resumes coherently.
- M2.12 adds the speed-scaled sizing and the pinned-loop byte cap
  (§14.1); M2.11 keeps the current bounded window.

### Domain (§13.1, §13.3, §13.8)

- `PracticeLoop` gains `color` (hex, default amber), `repeat_count`
  (`int | None`, `None` = infinite, 1…9999) and `boundary_fade`
  (default true). `PracticeState` invariant: `loop_enabled` requires
  `active_loop_id`.
- New ops (all undoable, in history): `add_loop`
  (`start_frames`, `end_frames`, optional `name`/`color` — server
  defaults "Loop N" / palette default), `update_loop` (patch;
  `repeat_count` distinguishes absent from null via
  `model_fields_set`), `delete_loop` (clears active + enabled when it
  was active), `duplicate_loop` ("<name> copy"), `set_active_loop`
  (null clears; clears `loop_enabled`), `set_loop_enabled`.
- Validation (§13.3): `0 ≤ start < end ≤ duration_frames` for
  create/update (422 `LOOP_RANGE_INVALID`, ready-required);
  `set_loop_enabled true` requires an active loop (409
  `NO_ACTIVE_LOOP`) and `(end - start) / sample_rate ≥ 0.1 s`
  (409 `LOOP_TOO_SHORT`, message names the 100 ms minimum; short loops
  may be saved but not repeated, §13.3.2–3). Exact frame boundaries are
  preserved — never expanded (§13.3.5–6).

### UI (§13.2)

- **Loops panel** (side panel, next to the mixer): the loop list with
  name, color swatch, duration and frame boundaries; click selects the
  active loop; buttons: create from selection, duplicate, delete;
  inline rename; color palette; repeat-count input (blank = infinite);
  fade toggle; the enable toggle (with the 100 ms explanation shown
  inline on `LOOP_TOO_SHORT`).
- **Numeric boundaries** (§13.2.2): start/end inputs in seconds
  (3 decimals) committed on Enter/blur.
- **Waveform overlay**: the active loop's range shaded in its color,
  boundary handles (drag, `HANDLE_HIT_PX` pattern of the selection
  layer) and body drag to move the interval, committed on pointerup.
- **`L`** toggles looping (ignored while typing in an input; no-op
  without an active loop).
- The playhead/readout already follow `transport.position`, which is
  now loop-mapped — the cursor follows the audio actually heard.
