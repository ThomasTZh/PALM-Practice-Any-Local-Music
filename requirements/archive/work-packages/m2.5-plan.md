# M2.5 plan — Implement bounded Demucs separation

Spec: `projectPlans/milestone2.md` §7. M2.4 produces the prepared input
(44.1 kHz stereo PCM + versioned normalization profile); M2.3 pins the
bundled `htdemucs_ft` baseline. This work package implements the versioned
windowed inference adapter, the short-input reference runner, and the
comparison gate. No API (M2.17), no validation/publication (M2.6).

## Resolved facts (2026-10-10, from the pinned demucs 4.1.0 source)

- `apply_model(model, mix, shifts, split, overlap, transition_power,
  device, num_workers, segment, pool, lock, callback, callback_arg)`
  (`demucs/apply.py`):
  - `segment` overrides the model segment — the memory-recovery lever
    (§7.5). `BagOfModels.max_allowed_segment` = the HTDemucs `segment`.
  - HTDemucs default `segment=10` s; the checked-in `htdemucs_ft.yaml`
    does not override it → the 7.5 s initial internal segment is within
    the validated maximum (§7.1).
  - `shifts>0` draws `offset = random.randint(0, int(0.5 × samplerate))`
    with **Python's `random`** module, per (model-in-bag, shift) →
    reproducibility hook: `random.seed(run_seed + window_index)`
    (§7.1 fixed recorded seed; §7.2.5).
  - `split=True` internal handling: segment_length = rate × segment,
    stride = (1 − overlap) × segment_length, triangular weights,
    weighted accumulation + division — the adapter reuses this inside
    each outer window (§7.2.4), never re-implements it.
  - `callback(dict)` fires **per internal segment** with keys
    `model_idx_in_bag`, `shift_idx`, `segment_offset`, `models` — the
    pinned progress/cancellation facility (§7.4, §7.6.1). Raising inside
    the callback triggers `pool.shutdown(wait=True, cancel_futures=True)`.
  - `htdemucs_ft` = `BagOfModels` of 4 identity-ensemble submodels;
    output `(1, 4, 2, length)`; labels = the model's declared
    `sources` (cross-checked against the registry — never a hard-coded
    index, M2.1 rule).
- M2.4: `NormalizationProfile` (v1: mode normal / full_channel_fallback /
  exact_silence; `scale = 1/max(rms_ref, 1e-4)`; reference mean/rms;
  `prepared_input_hash`). exact_silence ⇒ zero stems **without inference**.
- M2.2/M2.3 boundary pattern: the analysis env never imports the
  application; entry points are scripts run with the explicit
  `analysis/.venv/bin/python`; the checked-in registry is loaded by file
  path (`importlib.util`); HF-offline env vars are set before demucs
  import.
- Main env stays torch/demucs-free (guard test). Torch-free math belongs
  in the main env and is loaded by file path in the worker.

## Design

### Main env — `src/basseparate/media/windowing.py` (torch-free, numpy)

- `window_schedule(total_frames, window_frames, overlap_frames) ->
  list[tuple[int, int]]` — (offset, length) per outer window; stride =
  window − overlap; the last window is truncated to the track end; no
  empty windows; a track shorter than one window yields one window.
- `outer_window_weight(length, overlap, is_first, is_last) -> np.ndarray`
  — complementary raised-cosine weights: leading ramp
  `0.5 − 0.5·cos(πj/(O−1))` (skipped for the first window), middle 1,
  trailing ramp `0.5 + 0.5·cos(πj/(O−1))` (skipped for the last window).
  At every shared sample of adjacent windows the pair sums to exactly 1
  and never to 0. Ramps are always indexed against the full overlap O
  (a truncated last window keeps the same j/(O−1) phase, preserving
  complementarity). O ≥ 2 is a precondition (we use 8 s = 352,800).
- `pre_scale(x, mean, scale)` / `restore_scale(y, mean, scale)` —
  `x·scale − mean·… ` i.e. `(x − mean)·scale` and `y/scale + mean`
  (exact linear round-trip; float32 in/out).
- `accumulate_overlap(pending_sum, pending_w, stems, weight)` — numpy
  float64 overlap-add primitives used by the worker's incremental
  finalize/keep-tail scheme.

Tests: `tests/unit/test_windowing.py` — schedule coverage/exact
multiples/short-track/last-partial-window; complementarity (pair sum 1,
no zeros); weight endpoints; scale round-trip; accumulation invariant
(blend of two windows == their weighted average in the overlap, identity
outside).

### Analysis env — `analysis/separate.py` (the windowed adapter worker)

CLI: `--input <prepared.pcm> --profile <profile.json> --bundle-dir
<repo> --device <cuda:N|cpu> --out <staged-dir> --seed <int> --cancel
<file> [--segment 7.5]`.

Pipeline (§7.2, §7.4–7.7):
1. HF-offline env before demucs import; load registry by file path;
   verify the 5 artifact hashes (M2.3 pattern); `get_model("htdemucs_ft",
   repo=bundle_dir)`; cross-check `model.sources` against registry labels.
2. Profile gate: `exact_silence` → write four zero stem PCMs + run
   record, exit 0 **without loading the model**. Verify the input file
   hash against `prepared_input_hash`.
3. Per window (120 s / 8 s overlap, `window_schedule`):
   - seed `random` + `torch` with `run_seed + window_index`;
   - slice, `pre_scale` with the **same global profile** for every
     window (§7.2.3);
   - `apply_model(model, x, shifts=2, split=True, overlap=0.5,
     segment=effective_segment, device=..., callback=cb)`;
   - `restore_scale` (§7.2.6);
   - blend with `outer_window_weight`, float64 accumulation, divide;
   - finalize the non-overlap prefix **incrementally** to staged f32le
     stem files, written interleaved `(frames, 2)` — the prepared-input
     PCM convention; window blocks are time-contiguous, so appending
     them yields a valid whole-track interleaved stream. Keep only the
     8 s overlap tail in memory (§7.2.9–10).
4. Progress: work units = Σ_windows (models × shifts × internal
   segments); one unit per callback; JSON lines on stdout
   (`completed_units`, `total_units`, `fraction`, window/shift/segment)
   (§7.4).
5. Cancellation: cancel-file check between windows and inside the
   callback → `SeparationCancelled` → demucs cancels queued chunks →
   bounded graceful exit, staged outputs removed, run record
   `status: cancelled`, exit 2 (§7.6).
6. Memory recovery: `torch.cuda.OutOfMemoryError` / `MemoryError` →
   record failure + effective parameters, `empty_cache`, restart the
   complete run under the next validated segment (7.5 → 5 → 3 s),
   distinct staged dir per attempt (distinct cache identity); stop
   after bounded retries; final failure exits 3 with a JSON suggestion
   offering CPU/another device (§7.5). Stems from different profiles are
   never mixed.
7. Run record JSON: status, device, seed, window policy, per-attempt
   segment profile, shifts/internal overlap, profile version + hash,
   model identity (preset + artifact hashes), input hash, labels, frame
   count, timings, failures.

### Analysis env — reference runner + comparison gate (§7.3)

- `analysis/reference_separate.py` — upstream behavior on a short track:
  one whole-track `apply_model` call (same shifts/split/overlap/segment,
  same global pre-scale) — the reference the adapter is compared
  against.
- `analysis/compare_adapter.py` — the comparison gate: labels, shape,
  scale (per-stem RMS ratio), alignment (cross-correlation lag),
  numerical difference (per-stem max abs + spectral), boundary artifacts
  (difference localized at outer-window transitions vs interior), bass
  continuity around transitions. JSON report with documented thresholds.
  If boundary defects appear → new profile (more context/overlap) and
  re-run before release (§7.3 last rule).

### Evidence (git-ignored, `docs/evidence/`)

- Long-track run (≈8 min synthetic): host RSS bounded (1 min vs 8 min
  comparison), finite stems, run record.
- Comparison gate on a short track: adapter vs reference.
- Cancellation: cancel-file mid-run → staged cleanup, exit 2.
