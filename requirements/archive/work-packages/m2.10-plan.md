commit. M2.9 is committed at `3e12570` + ledger `37e1eeb`.

## Design (as built)

### Engine facts (measured, authoritative)

Read from the upstream source (`signalsmith-stretch.h`, the demo's
`web/web-wrapper.js`) and verified against the real artifact with Node
probes:

- `seek(inputs, inputSamples, rate)` copies only the **last**
  `blockSamples + interval` = 5760 frames (@48k) of the fed buffer into
  the STFT input ring; the fed window is 7200 = 5760 + one interval.
  The analysis block's centre sits `inputLatency` before the window
  end.
- The synthesis places a block's centre `outputLatency` **output**
  frames after the render position where the block was created
  (a new spectrum is processed every `interval` *output* samples,
  independent of the rate).
- **Rolling law (validated):** with the audible cursor `S` at the
  quantum's start,

      windowEnd = round(S + rate·outLat + inLat)

  The upstream live-playback reference uses the same law (its
  `inputTime` is evaluated at `now + outLat`, then adds `inLat`).
- `process(0, N)` with `N ≤ interval` keeps every new analysis block
  the first after a seek (`timeFactor = 1/rate`); the per-quantum
  rolling seek is therefore required, not optional.
- **Measurements** (impulse train on a live 200 Hz background, scalar
  artifact @48k): impulse residuals +45…+75 **output frames** (≈1 ms)
  at 0.25×/0.5×/1×/2×, constant over 600 quanta (no drift). Step and
  ramp read-back probes show wider transition-shape artifacts (up to
  ~1000 output frames at 0.25×); they measure the smeared edge, not
  the mapping — the spec's §12.3.6 impulse probe is the reference.
- **Wet start:** after `reset()` the overlap-add accumulator is silent
  (first-quantum mean 0.0005); ~2880 output frames reach ≈98 % level,
  **5760** reach full (measured first-quantum means 0.1000 / 0.1008 /
  0.0994 at 1× / 2× / 0.5×). The warm-up is alignment-neutral and
  costs ≈3.6 ms per 5760 frames (Node), spread ≤ 8 quanta per callback
  (≈16 ms wall time).
- `set_rate` / `set_rate_now` / `effective_rate` stay as probes; the
  playback path samples its own ramped rate once per quantum and
  passes it to every `seek`.

### Wrapper API (rebuilt artifacts, committed)

`stretch_wrapper.cpp` exports (letters in the built artifacts):
`f` configure, `g` input latency, `h` output latency, `i` window
length (7200 @48k), `j` seek, `k` process, `l` set rate, `m`
set rate now, `n` effective rate, `o` reset, `p` pool offset, `q`
pool input frames; `d` memory, `e` start. The pool is
`[inL(7200) | inR(7200) | outL(4096) | outR(4096)]`. `BUILD.md`
records the manifest hashes.

### Protocol (transport ↔ worklet)

- `seek` message: `{type:'seek', frame, audibleFrame, generation}`.
  `frame` = the fetch frame `max(0, B − PRE_ROLL_FRAMES)` with
  `PRE_ROLL_FRAMES = 12_288` (covers the largest need: warm-up
  11 520 @2× plus the first window's back-reach); `audibleFrame` = the
  requested boundary `B`. The worklet seeks every source to `frame`
  and sets its audible cursor to `audibleFrame`.
- `anchor` message: exact pairs `{frame, time, paused, rate}` — the
  audible cursor `frame` plays **exactly** at context time `time` (the
  quantum's end where the cursor sits there), `rate` = the worklet's
  ramped rate. The transport extrapolates with the anchor's rate and
  never subtracts a latency or derives position from elapsed wall time
  (§12.7).
- `stretch-ready` unchanged.

### Worklet data path (§12.3–12.4)

- Mix ring (stereo, 16 384 frames) fed from the source stems in
  ≤4096-frame chunks (per-stem gain/pan/mute/solo applied
  pre-stretch, §11.1 order); two taps read it:
  - **dry** = the exact ring read at `S` (bit-identical to the
    no-engine path, §12.4);
  - **wet** = the rolling seek (fill the window ending at
    `round(S + r·outLat + inLat)`, `seek(windowLength, r)`,
    `process(0, N)`, zero-pad outside `[0, frameCount)`).
  Per-sample dry/wet gain interpolation, then the master gain.
- **Wet start:** `reset()` + a silent warm-up (5760 output frames of
  the rolling seek, output discarded, ≤8 quanta per callback, starve →
  break). The audible cursor does not move during the warm-up; the
  first audible quantum is the requested boundary at full level.
- **Crossfades (~5 ms) only ever run while both taps are at exactly
  1×:** dry→wet = crossfade first, then the rate ramp; wet→dry = ramp
  to 1× first, then the crossfade. Rapid flips reverse within the same
  rules; the sum is always two copies of the same 1× signal.
- **EOF (§12.6):** no tail flush. The window tail zero-pads past
  `frameCount`; emission stops when `S ≥ frameCount` (natural window
  fade, no extra blank), the reported position clamps to `frameCount`,
  `ended` fires once.
- **Underrun:** the ring cannot cover `min(windowEnd, frameCount)`
  (wet) or the dry read → silence, no cursor advance, one notification
  per episode (suppressed while flushing / when nothing was ever
  buffered).

### Transport ledger (§12.1–12.2, §12.7)

- Exact anchors feed `consumedFrame`/`anchorTime`/`anchorRate`;
  `getAudiblePosition()` = `consumedFrame + (now − anchorTime) ·
  rate · anchorRate` (fallback `speed`; `setRate` sets it
  optimistically). `pause()` and the fill budget use `anchorRate`.
- Segments stay bounded and are retained across seeks (§12.2).
- Pre-roll fetch: `flushBookkeeping` sets
  `fetchedFrame = max(0, B − 12_288)`, `genStartFrame = B`; the fill
  fetches from the pre-roll; the shared path's flush-ack resets the
  writer to the pre-roll. `load` (parked frame) and `rebind` (context
  loss) apply the same pre-roll so a wet start never starves.
- §12.5 diagnostics: `controlResponseLatencySeconds =
  (speed·outputLatency + inputLatency) / sampleRate` (0 without an
  engine; the master gain is post-stretch, so it is immediate).
- Read-ahead consequence (documented, visible in diagnostics): the
  worklet reads up to `S + r·outLat + inLat` (max 8640 frames @2×) →
  mixer/control-response latency ≈120–180 ms @48k.

### Caveats (accepted, documented in the evidence)

- A **wet** seek's audible content starts after the ≈16 ms silent
  warm-up; the transport's ledger names the audible boundary `B`, so
  the position mapping is correct — the wall-clock onset of sound
  trails `B` by the warm-up (monitoring-only).
- Content with sharp edges near a rate change shows the engine's
  transition-shape smearing: ≤ ~1 ms at 1×, up to ~20 ms of output at
  0.25× in the worst step case. Impulse centroids stay within ±1.5 ms
  at every rate.
- At the very start of a file (`B < warm-up·rate`) the warm-up is
  naturally short (the window head is zero-padded) and the engine
  envelope is accepted.
