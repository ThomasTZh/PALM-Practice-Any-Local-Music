# M2.8 plan — Add aligned tracks and the stem mixer

**Status (2026-10-13):** Phase 1 (this plan + ledger) done. Phases 2–7
pending. All M2.7 work is committed (`ac12159`); the tree is clean.
See `docs/implementation-status.md` for the full resume state.

Spec: `projectPlans/milestone2.md` §10. M2.7 made separation results
selectable (`practice_state.active_result_set_id` + the
`set_active_result_set` command). This work package turns a selected
result set into a **usable practice surface**: the original audio as a
reference track plus the active stem group (bass pair or four stems)
shown as aligned waveforms, a per-track mixer (mute / solo / gain /
pan / visibility / color / height), a shared-timeline multi-source
transport, and monitoring safety (peak meters + a default-on limiter).

## Scope guardrails

- No new separation runs, no cache changes (M2.7 closed), no
  time-stretch (M2.9), no loops UI beyond what `PracticeState` already
  carries.
- The mixer is **monitoring-only**: §10.3.8 — "avoid changing sample
  storage". No write path touches stem assets; raw-stem exports
  (M2.13+) read the untouched files, and the limiter stays out of them
  (§10.6.7).
- Frontend is the bulk of this package; the backend changes are: four
  new command ops, two domain adjustments, and one read-only detail
  route.

## Design

### Domain + commands (Phase 2)

`domain/practice.py`:

- `TrackSettings.color: str` — new field, hex pattern
  `^#[0-9a-fA-F]{6}$`, default `"#8fa3bf"` (neutral). The frontend
  applies the role-palette color as the *displayed* initial value; the
  domain stays palette-agnostic. No schema migration: `tracks` lives
  in the project record JSON (pydantic default fills old rows).
- `MAX_GAIN`: `2.0` → `10 ** (12.0 / 20.0)` (≈ 3.981 = +12 dB,
  §10.3.2). The floor stays `0.0` — exact silence is `mute`
  (§10.3.3). Affects `TrackSettings.gain` and `PracticeState.master_gain`
  ranges; update the unit tests that assert the old 2.0 cap.
- `PracticeState.monitoring_limiter`: default `False` → **`True`**
  (§10.6.3 "default the limiter on"). Existing rows keep their stored
  value; only new/absent state defaults on.

New ops in `domain/commands.py` (all undoable — none join
`HISTORY_EXCLUDED_TYPES`):

- `SetTrackSettingsOp` — `{ type: "set_track_settings", stem_role,
  gain?, balance?, mute?, solo?, visible?, display_height?, color? }`.
  Patch semantics: `None` = unchanged; at least one non-`None` field
  required. `stem_role` must be a valid `StemRole` value. Applies to
  `practice_state.tracks[stem_role]` (creates the entry with defaults
  if absent).
- `SetPlaybackModeOp` — `{ type: "set_playback_mode", mode }`
  (§10.4.5–6: the explicit Original/Stem Group selector). Pre-validation
  in `apply_command`: a stem mode with no `active_result_set_id` raises
  a new `PlaybackModeRequiresResultSetError` → 409
  `PLAYBACK_MODE_REQUIRES_RESULT_SET` (the existing `PracticeState`
  validator is the backstop; the explicit error keeps the API
  diagnostic).
- `SetMasterGainOp` — `{ type: "set_master_gain", gain }`
  (0 … MAX_GAIN).
- `SetMonitoringLimiterOp` — `{ type: "set_monitoring_limiter",
  enabled }`.

`_apply_op` gains the four handlers (same `model_copy(update=…)`
pattern as `set_active_result_set`). Undo/redo come free from the M1.15
history snapshots (`practice_state` is already in the snapshot — M2.7).

New read-only route (`api/result_set_routes.py`):

- `GET /api/v1/projects/{project_id}/result-sets/{result_set_id}` →
  `ResultSetDetail`: the result set (id, created_at,
  validation_status, cache_key) + stems (`id`, `role`,
  `display_name`, `audio_asset_id`, `sample_rate`, `channel_count`,
  `frame_count`) + provenance from the run (`engine_version`,
  `adapter_version`, `model_manifest_id`, `model_manifest_hash`) —
  feeds §10.1.6 "label generated stems and source provenance". 404 when
  the set is missing or belongs to another project. (M2.17 keeps the
  storage report/cleanup routes; this one is a UI data need.)

Contracts regenerated (`openapi.json` + `frontend/src/api/schema.ts`).

### Frontend state plumbing (Phase 3)

- `api/commands.ts`: `toCommandResult()` and `getProjectSnapshot()`
  currently **drop** `practice_state` — map it. `ProjectSnapshot`
  gains `practiceState: PracticeState | null`.
- `projects/useProjectCommands.ts`: the hook owns `practiceState`
  (initial from the snapshot, updated from every `CommandResult`).
  Mixer ops are **immediate** sends (like marker ops) — never debounced;
  view-style debouncing is for viewport/selection only.
- `api/result-sets.ts` (new): `fetchResultSetDetail(projectId,
  resultSetId)` with snake→camel mapping, matching the
  `waveform.ts` client style.
- Track settings accessors: `effectiveTracks(practiceState, stems)` —
  merges `practice_state.tracks` with per-role defaults (palette
  color, 0 dB, center, visible, height 1) so the UI never handles
  missing entries.

### Mixer DSP in the worklet (Phase 4)

One AudioWorklet processor consumes **all** active sources and mixes
them — a shared position cursor makes drift between stems impossible
(spec acceptance: "stems never drift relative to each other"). Separate
per-stem worklet nodes with WebAudio gain nodes would each consume at
their own timing and cannot guarantee alignment.

`playback/worklet-processor.js` (+ `.d.ts`):

- `ConsumptionState` (M1.12, unchanged) is instantiated **per source**
  — same `sampleRate` / `frameCount` for all (validated at prepare,
  §10.5.1–3). `PcmProcessor` gains:
  - `initMix(sources: [{ sampleRate, channelCount, frameCount }])` —
    N consumption states, shared cursor.
  - `setTrack({ index, gain, balance, mute, solo, channels })` and
    `setMaster({ gain })` — per-render-quantum reconfiguration.
  - `enqueue(index, buffers)` / `attachShared(index, sab)` — the M1
    data paths, per source index.
- Per-quantum mixing (inside `process`):
  1. Eligibility (§10.4): `anySolo = ∃ solo`; a track sounds only if
     `!mute && (!anySolo || solo)` — mute overrides solo (§10.4.3);
     hidden tracks are **not** silenced (§10.4.4 — visibility is a UI
     concern only).
  2. Gain law (§10.3): linear `gain` (UI converts dB via
     `10^(dB/20)`); per-track **5 ms linear ramp** on any parameter
     change (≈ 239 samples @ 48 kHz, ramped per sample inside the
     quantum) — §10.3.7, no clicks.
  3. Pan (§10.3.4–6): stereo track → balance attenuates the opposite
     side, `gL = 10^(-3b/10)`, `gR = 10^(3b/10)` (3 dB/side; center =
     both 1.0, channels preserved); mono track → equal-power
     `gL = cos(θ)`, `gR = sin(θ)`, `θ = (b+1)·π/4`.
  4. Sum L/R across tracks → `master_gain` → output channels.
  5. Meters (§10.6.1): per-track output peak + master peak computed
     per quantum, reported with the existing `consumed` message
     (no extra `AnalyserNode` plumbing; works for muted tracks → 0).
- Underrun (§10.5.7): **any** source underrunning raises the group
  underrun flag; the transport pauses the whole active group (buffered,
  §10.5.6 — muted stems keep consuming so unmute is immediate).
- Legacy single-source path: `init` (1 source, no mix messages) keeps
  working so M1 tests and the original-only mode run one code path.

### Multi-source transport (Phase 5)

`playback/transport.ts` — `PcmTransport` generalized:

- Constructor takes `sources: SourceSpec[]` (`assetId`,
  `sampleRate`, `channelCount`, `frameCount`) — length 1 = today's
  behavior (original track only).
- **Prepare** (§10.5.1–3): for every source, fetch asset metadata and
  validate `sampleRate === project rate` and
  `frameCount === project duration` (M2.6 guarantees both; a mismatch
  is a hard prepare error, not a silent resample). All sources share
  the project→playback mapping (`playbackPosition`, unchanged).
- **Fetch layer**: `fetch-worker.ts` manages N per-asset queues behind
  the single-producer worker (one worker, N `FetchSource` rings —
  `WorkerFetchSource` / `DirectFetchSource` gain an index). Muted
  sources keep fetching (§10.5.6).
- **Group underrun**: any `underrun` message → pause the group
  (existing `pausing` state, extended to "refill all sources before
  resume").
- **Latency** (§10.6.5): when the limiter is enabled, the documented
  limiter delay constant (`LIMITER_DELAY_SECONDS = 0.010`, 10 ms —
  conservative upper bound for the compressor attack path) is added to
  the reported transport latency; the constant is documented in
  `worklet-processor.d.ts` / `transport.ts` and covered by a test.
- Worklet messages: the M1 protocol extended with `initMix` /
  `setTrack` / `setMaster` / indexed `enqueue` / `attachShared`;
  `consumed` gains `peaks: number[]` (per track) + `masterPeak`.

### UI — aligned tracks + mixer (Phase 6)

`App.tsx` restructures the project view into a track stack:

- **Track list** (§10.1): the original (reference, always present) +
  the active stem group from `practice_state` (`bass_pair` → bass +
  residual; `four_stems` → vocals/drums/bass/other). Stem data comes
  from `fetchResultSetDetail` on the active set.
- **Shared viewport** (§10.1.4): one zoom/pan state drives every
  lane (the M1 `Viewport` model, unchanged); each track keeps
  **independent lane height** (`display_height`, 0.25–2) and
  **independent amplitude zoom** (per-track `ampScales` pattern from
  the M1.10 channel display).
- **Per-track lane**: reuses `useWaveform` (M1.10 tiled endpoints —
  §10.1.7, fetch only visible tiles §10.1.8) + `drawLaneWaveform`;
  label = `display_name` + provenance line (model + engine version,
  §10.1.6); the original is labeled "Original".
- **Mixer strip per track** (§10.2): mute (M), solo (S), gain slider
  **−60 … +12 dB** (stored as linear via `10^(dB/20)`), pan/balance
  slider (center default), visibility toggle (§10.1.9 — hiding never
  mutes), color swatch, height slider. Defaults: 0 dB, center, mute
  off, solo off (§10.2).
- **Mode selector** (§10.4.5–6): Original / Bass pair / Four stems —
  sends `set_playback_mode` (with `set_active_result_set` when no set
  is active yet — M2.7's selection command; the 409 from a stem mode
  without a set is surfaced as a notice prompting selection).
- **Monitoring panel** (§10.6): master output peak meter (dBFS) +
  per-track peaks; limiter toggle (default **on**, state visible);
  limiter = WebAudio `DynamicsCompressorNode` on the monitoring path
  only (worklet output → compressor → destination), threshold
  **−1 dBFS** (§10.6.4), high ratio; it never touches stored samples
  (§10.6.7).
- Solo semantics are enforced in the worklet (Phase 4), not the UI;
  the UI only sends the flags.

  meter/limiter rendering; `render` painters reuse (no new painter
  tests beyond lane-height stacking).
