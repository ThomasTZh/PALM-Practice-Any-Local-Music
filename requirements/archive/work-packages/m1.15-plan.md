# M1.15 plan — Markers, persistence, and undo/redo

Spec: `projectPlans/milestone1.md` §17. Full-stack. Adds a marker model
and per-project working state (selection, viewport, channel display,
monitoring volume, last position, follow-playhead), a project-command
endpoint with revision validation (`409` on stale), server-side
undo/redo history, working autosave with debounced view state, and
restore-on-reopen. Acceptance (§17): annotations and working state
survive a restart; introduced manual edits can be undone and redone.

Out of scope: looping (M1.16 territory per spec §18 context), chord /
note / bar readouts (forbidden in Milestone 1).

## 2. Marker model (§17.1)

`MarkerRecord` (frozen pydantic, `domain/marker.py`):

- `id: Uuid`, `project_id: Uuid`
- `position_frames: SamplePosition` — inclusive bounds: `0` and exactly
  `duration_frames` are valid (§17.1).
- `label: str` — 1–80 chars after trim, no control chars (same
  validator style as project names).
- `color: str` — pattern `^#[0-9a-f]{6}$`.
- `created_at` / `updated_at: UtcTimestamp`.

Defaults for new markers: label `"Marker"`, color `#e11d48`.

`ProjectRecord` gains `markers: list[MarkerRecord]` (default `[]`) and
`working_state: WorkingState` (default). Post-init checks (existing
pattern): an empty project has no markers; every marker position is
within `[0, duration_frames]` when duration is known; working-state
positions are within range.

## 3. Working state (§17.5)

`WorkingState` (frozen, `domain/project.py`):

```
selection_start: int | None     # present together with selection_end
selection_end:   int | None
viewport: ViewportState | None  # { start_frame: int, frames_per_css_pixel: float > 0 }
channel_display: ChannelDisplay # { linked: bool, scales: list[float] (0.25..16, ≤8) }
monitoring_volume: float        # 0..2 (UI shows 0–200 %)
last_position_frames: int       # 0..duration_frames
follow_playhead: bool           # default True
```

Selection pair must be present together with `start ≤ end`. All
frame-valued fields validate against `duration_frames` in
`ProjectRecord.model_post_init` (range checks), mirroring the existing
source-field consistency style.

## 4. Commands (§17.3/§17.4)

`POST /api/v1/projects/{project_id}/commands`

Request body:

```
{
  "command_id": uuid,
  "idempotency_key": str (1..128),
  "base_revision": int ≥ 0,
  "op": { "type": "<op>", ... }
}
```

Ops (discriminated on `type`; `domain/commands.py`):

| op | payload | history |
| --- | --- | --- |
| `add_marker` | `position_frames`, `label?`, `color?` | yes |
| `update_marker` | `marker_id`, `position_frames?`, `label?`, `color?` | yes |
| `delete_marker` | `marker_id` | yes |
| `set_selection` | `start_frames?`, `end_frames?` (both null clears) | yes |
| `set_viewport` | `viewport: {start_frame, frames_per_css_pixel} \| null` | yes |
| `set_display` | `channel_display: {linked, scales}` | yes |
| `set_monitoring_volume` | `volume: 0..2` | yes |
| `set_position` | `position_frames` | **no** (§17.4.10) |
| `set_follow_playhead` | `follow_playhead: bool` | yes |

Behavior:

1. Transaction (`BEGIN IMMEDIATE`): read project row; missing → 404.
2. `row.revision != base_revision` → **409**
   `{ code: "stale_revision", current_revision }` (§17.4.1/§17.4.6).
3. Position-bearing ops on an empty project (no `duration_frames`) →
   409 `{ code: "project_not_ready" }`.
4. Apply op in memory; `UPDATE projects` (working state JSON,
   `revision + 1`, `updated_at`, `history_seq`); marker table
   insert/update/delete; insert one `project_history` row for
   history-worthy ops (§17.4.2–§17.4.4).
5. Response 200: `{ revision, markers, working_state, can_undo,
   can_redo }` — the resulting state (§17.4.5).

Idempotency: same key + same body hash → cached 200 replay; same key +
different body → 409 (existing `IdempotencyConflictError`).

Undo/redo:

- `POST /projects/{id}/undo` and `/redo` with `{ base_revision }` —
  same staleness check.
- No entry → 409 `{ code: "nothing_to_undo" | "nothing_to_redo" }`.
- Moving the pointer does not append history; it bumps `revision`.

## 5. History model (§17.4.3/§17.4.9/§17.4.10)

Table `project_history`: `(id, project_id, seq, kind, before_json,
after_json, created_at, UNIQUE(project_id, seq))`.

- `projects.history_seq` = seq of the newest applied entry (`-1` =
  none).
- **Snapshots exclude `last_position_frames`** (replaced by a sentinel
  on write) so undo/redo never moves the playhead back to a position
  the playback clock had passed (§17.4.10). Restore applies the
  snapshot and keeps the current `last_position_frames`.
- Undo: restore `before_json` of row `history_seq`; `history_seq -= 1`.
- Redo: restore `after_json` of row `history_seq + 1`;
  `history_seq += 1`.
- New edit: `DELETE` rows with `seq > history_seq` (redo branch,
  §17.4.9), insert row `seq = history_seq + 1`.
- Depth cap 200: on insert, delete the oldest row with
  `seq <= history_seq` when the project exceeds 200 rows.
- A drag / zoom / pan gesture is one client-side command (single
  `apply_command`) → one history entry (§17.4.7/§17.4.8).

## 6. Migration 6 (`db.py`)

```sql
ALTER TABLE projects ADD COLUMN working_state TEXT NOT NULL DEFAULT '{}';
ALTER TABLE projects ADD COLUMN history_seq INTEGER NOT NULL DEFAULT -1;
CREATE TABLE markers (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  position_frames INTEGER NOT NULL CHECK (position_frames >= 0),
  label TEXT NOT NULL,
  color TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_markers_project ON markers(project_id);
CREATE TABLE project_history (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  seq INTEGER NOT NULL,
  kind TEXT NOT NULL,
  before_json TEXT NOT NULL,
  after_json JSON NOT NULL,
  created_at TEXT NOT NULL,
  UNIQUE (project_id, seq)
);
CREATE INDEX idx_history_project ON project_history(project_id, seq);
```

Existing rows get `working_state = '{}'` (defaults) and empty marker
sets — no data migration needed.

## 7. Frontend command flow

`useProjectCommands(projectId)` (hook) owns:

- Authoritative state: `revision`, `markers`, `workingState`,
  `canUndo`, `canRedo` — updated only from server responses (no
  optimistic mutation).
- **Serialized writes** (§17.5.4): a per-tab queue; each `send(op)`
  appends and the queue processes one at a time; `pendingCount` drives
  the "Saving…" indicator (§17.5.7).
- **Debounce** (§17.5.2): `scheduleView(op)` coalesces view-state ops
  (viewport / selection / display / volume / follow) to one send per
  op type after ~1 s of quiet.
- **Position** (§17.5.3): `notePosition(frame)` sends
  `set_position` immediately on pause and at most every 5 s while
  playing; `set_position` is never queued through the view debounce
  and never recorded in history.
- **Flush** (§17.5.5): `flush()` (on ProjectView unmount / navigation)
  sends all pending debounced ops and awaits the queue.
- **Stale** (409 `stale_revision`): refetch the project (GET) to
  resync state, clear the queue, surface a one-line "Project changed
  elsewhere — reloaded" notice.
- `undo()` / `redo()` use the current `revision` as base.

## 8. Editor marker UI (§17.2)

New editor props: `markers`, `selectedMarkerId`, `onAddMarker(frame)`,
`onMoveMarker(id, frame)`, `onSelectMarker(id | null)`,
`onSeekToMarker(frame)`, `onUndo`, `onRedo`, `canUndo`, `canRedo`,
`initialViewport`, `initialSelection`, `initialChannelDisplay`,
`initialFollow`.

- **Drawing**: the marker row gets a canvas (ruler-aligned) drawing a
  flag per marker (color fill, label truncated to ~12 chars, selected
  marker outlined); each lane's existing `markers` layer draws a 1-px
  tick. Drawn in the existing draw pipeline (redrawn with the view).
- **Add at playhead** (§17.2.1): "Add marker" button in the marker
  row → `onAddMarker(playheadSource.getPosition())`.
- **Add at ruler position** (§17.2.2): double-click the ruler →
  `onAddMarker(frame at pointer)`.
- **Rename / exact frame / color / delete** (§17.2.3/5/6/7): marker
  list in the marker row — one row per marker: color swatch (cycles a
  6-color palette on click), editable label input, exact-frame input
  (frames; time shown), delete button. Edits commit one
  `update_marker` command on blur / Enter / click.
- **Select without editing** (§17.2.9): single click on a flag or list
  row selects (highlight only, no edit focus, no seek).
- **Drag** (§17.2.4): pointer-down on a flag → drag previews on the
  lane canvases (local only); pointer-up commits exactly one
  `onMoveMarker(id, frame)` (§17.4.7).
- **Double-click to seek** (§17.2.10): double-click a flag →
  `onSeekToMarker(frame)` (app seek while paused/playing) + select.
- **Prev/next** (§17.2.8): marker-row buttons seek to the nearest
  marker before / after the playhead and select it.
- **Undo/redo buttons**: editor toolbar, disabled by `canUndo` /
  `canRedo`, call `onUndo` / `onRedo`.

## 9. Autosave + restore wiring (App.tsx)

- `ProjectView` creates the hook once the project is loaded and passes
  `workingState` down:
  - editor `initialViewport` / `initialSelection` (applied on first
    ready, fit view when absent),
  - editor `initialChannelDisplay` (replaces the `localStorage` amp
    read as the primary source; legacy key read only when the server
    state is at defaults) and `initialFollow` (same pattern for
    `basseparate.playheadFollow`),
  - panel monitoring volume seed,
  - transport park: seek to `last_position_frames` while paused
    (§17.6.4/§17.6.5 — remain paused).
- Change callbacks: editor view / selection / display / follow changes
  → `scheduleView(...)`; marker ops → `send(...)` immediately;
  volume → `scheduleView(set_monitoring_volume)`; panel position →
  `notePosition` (pause + 5 s).
- Unmount / project switch → `flush()`. Page close: best-effort
  `sendBeacon` of pending view state (§17.5.6).
- Pending indicator: "Saving…" chip in the project header while
  `pendingCount > 0` or a debounce is armed.

## 10. Reopen + recovery (§17.6/§17.7)

- Reopen: asset / representation / cache handling already exists
  (M1.3–M1.13); M1.15 adds marker + view + position + follow restore
  (above) and keeps playback paused.
- Recovery: interrupted jobs already restart from a safe boundary
  (job manager `interrupted → queued`); uploads resume from the
  on-disk manifest; missing waveform cache rebuilds via a new waveform
  job. M1.15 surface: when the canonical asset file is missing, the
  project view reports the missing source representation and offers
  "Regenerate from original" (creates a `canonical_decode` job via the
  existing `POST /projects/{id}/jobs`); missing original with a valid
  canonical plays with a provenance warning line. Audit first; add
  only what is absent.
