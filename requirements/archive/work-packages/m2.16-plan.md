# M2.16 — Open portable projects (spec §18)

## Objective

Open a `.basseparate` archive produced by M2.15 into the working store as a
new, playable project. Acceptance (§18): the project opens and plays on a
clean app installation with all model directories absent and network access
disabled.

## Scope

- Browser-compatible input: normal file picker + drag-and-drop for
  `.basseparate`; transfer over the existing bounded chunked-upload
  mechanism with a dedicated `max_project_archive_bytes` cap (§18.1).
- Validate before import (§18.2): ZIP directory, size/member limits, bounded
  manifest, version checks, path safety, member-set equality, per-member
  size + hash. No blind `extractall()`.
- Untrusted embedded database handling (§18.3): read-only, no extensions,
  explicit column queries, application-schema validation, no SQL from the
  archive.
- Asset restoration (§18.4): stage, verify, dedupe content-addressed
  objects, publish missing ones, import records transactionally, remap IDs,
  expose the project only after commit.
- ID policy (§18.5): default "open as a new working copy" (new project ID,
  archived identity kept as provenance); `as-archived` mode only when the
  archived ID is free.
- Optional-member failures (§18.6): missing waveform cache → rebuild on
  demand; missing playback-rate cache → regenerate on demand; missing
  model → irrelevant for playback; missing essential → reject with the
  damaged member named.
- State restoration (§18.7): active result set, mixer, loops, speed,
  viewport/markers, last position — all carried by the portable DB rows and
  restored with the import; the project opens paused (existing frontend
  behavior); playback representations already exist (canonical/downmix/
  stems) or are regenerated on demand.

Out of scope: separation job scheduling (M2.17), re-saving an opened copy
(works via M2.15 unchanged), archive format changes (M2.14).

## Design

### 1. Configuration (new keys, `config.py`)

| Key | Default | Meaning |
|---|---|---|
| `max_project_archive_bytes` | 160 GiB | Transfer cap for `.basseparate` uploads. Deliberately **not** the 20 GiB media-import value: a maximal 20 GiB source project carries original + canonical + downmix + 4 stems + residual ≈ 7.5× source size, all stored uncompressed in the archive (≈150 GiB). The reserve-time free-disk check remains the real safety bound. |
| `max_archive_uncompressed_bytes` | 160 GiB | Sum of all member uncompressed sizes (central-directory check + streaming re-check during extraction). |
| `max_archive_member_count` | 10 000 | Member-count safeguard; real archives carry < 100 members (assets + cache tiles + provenance). |

All three are validated like the existing caps (positive ints; the
uncompressed cap must be ≥ the transfer cap).

### 2. Transfer (reuses the bounded upload mechanism, §18.1)

- Second `UploadManager` instance in `app.py`:
  `app.state.archive_uploads = UploadManager(uploads_dir=paths.runtime /
  "archive-uploads", chunk_size=config.import_chunk_bytes,
  max_import_bytes=config.max_project_archive_bytes)`.
  Sessions persist across restarts via their on-disk manifests, exactly
  like media uploads; no DB rows (an open session is not tied to a project
  until the import commits).
- Chunk protocol identical to imports: sequential offsets,
  `X-Chunk-SHA256` header, idempotent replay, 409 on offset mismatch.

### 3. Routes (`api/open_routes.py`, prefix `/api/v1`)

| Route | Behavior |
|---|---|
| `POST /projects/open` | Body `{filename, declared_byte_count, open_mode?, project_name?}`. `filename` must end in `.basseparate` (422 `ARCHIVE_BAD_FILENAME`), no control chars. `open_mode` ∈ `{"new-copy" (default), "as-archived"}`. Declared size over the cap → 413 `ARCHIVE_SIZE_LIMIT`. Reserves space in `archive_uploads` (507 `OPEN_NO_SPACE` on failure). 201 `{open_session_id, chunk_size, max_project_archive_bytes}`. |
| `PUT /projects/open/{session_id}/chunks?offset=` | Same protocol as `PUT /imports/{id}/chunks`. 404 `OpenSessionNotFoundError`. |
| `POST /projects/open/{session_id}/complete` | Synchronous (FastAPI threadpool — pure file I/O + DB, no DSP; same posture as the M2.15 save route). Runs the §4 pipeline. 201 `{project_id, name, status}` (the opened working copy). |
| `GET /projects/open/{session_id}` | Session state: received/declared bytes, state, last error. |
| `POST /projects/open/{session_id}/cancel` | Removes session files. Idempotent. |

`complete` requires a fully acknowledged transfer (offset == declared ==
file size), mirroring `complete_import`.

### 4. Validation + extraction (`portable/open.py`)

Error family (new, in `api/errors.py`; all 422 unless noted):
`ARCHIVE_NOT_ZIP`, `ARCHIVE_SIZE_LIMIT` (413), `ARCHIVE_MEMBER_LIMIT`,
`ARCHIVE_UNCOMPRESSED_LIMIT`, `ARCHIVE_MANIFEST_INVALID`,
`ARCHIVE_VERSION_UNSUPPORTED`, `ARCHIVE_MEMBER_UNSAFE`,
`ARCHIVE_MEMBER_MISSING`, `ARCHIVE_MEMBER_CORRUPT`, `ARCHIVE_SCHEMA_MISMATCH`,
`ARCHIVE_DB_INVALID`, `OPEN_NO_SPACE` (507), `OPEN_ID_CONFLICT` (409).

Pipeline, in order (first failure wins; staging is deleted on any failure):

1. `zipfile.ZipFile(archive_path)`; `BadZipFile` → `ARCHIVE_NOT_ZIP`.
2. `namelist()`: count > `max_archive_member_count` →
   `ARCHIVE_MEMBER_LIMIT`.
3. Sum of central-directory `file_size` > `max_archive_uncompressed_bytes`
   → `ARCHIVE_UNCOMPRESSED_LIMIT`.
4. Bounded manifest read: `manifest.json` must exist; member size > 1 MiB →
   `ARCHIVE_MANIFEST_INVALID`; `PortableManifest.model_validate_json` must
   succeed.
5. Versions: `format_id == FORMAT_ID` and
   `container_version == CONTAINER_VERSION` → else
   `ARCHIVE_VERSION_UNSUPPORTED`; `1 ≤ project_schema_version ≤
   PROJECT_SCHEMA_VERSION`.
6. Member safety, per `ZipInfo`:
   - absolute path or `..` component → `ARCHIVE_MEMBER_UNSAFE`;
   - symlink (`(external_attr >> 16) & 0o170000 == 0o120000`) → unsafe;
   - encrypted (`flag_bits & 0x1`) → unsafe;
   - directory entries (unexpected file type) → unsafe;
   - duplicate names after `PurePosixPath` normalization → unsafe.
7. Member-set equality: archive names == manifest member names (exact set;
   unknown members and manifest members with wrong
   `category_for(name)` classification are rejected).
8. Essential presence: every `essential` manifest member must be in the
   archive, else `ARCHIVE_MEMBER_MISSING` (listing the members).
9. Free space: `shutil.disk_usage` on the data root (staging + not-yet
   present store objects + 1 GiB margin) and the runtime root (source
   original + margin) → `OPEN_NO_SPACE`.
10. Staged extraction into `data/portable/.import-staging/<uuid>/`:
    - members in manifest order; stream `zf.open(info)` in 1 MiB chunks;
      running SHA-256; partial file + `os.replace`;
    - actual size ≠ manifest `uncompressed_size_bytes` or hash mismatch:
      essential → `ARCHIVE_MEMBER_CORRUPT` (member, expected, actual);
      optional → drop the member (treated as absent, §18.6).
11. The staged `project.sqlite` is then handled per §5.

### 5. Database handling + import (§18.3, §18.4, §18.5)

Read (untrusted):

1. `sqlite3.connect("file:<staged>?mode=ro", uri=True)`,
   `enable_load_extension(False)` explicit, `PRAGMA query_only = ON`.
2. `PRAGMA user_version` must equal `DATABASE_SCHEMA_VERSION` (10 at
   release) → else `ARCHIVE_SCHEMA_MISMATCH`. Expected tables ⊇ {projects,
   assets, project_assets, imports, representations, waveform_caches,
   markers, project_history, separation_runs, separation_result_sets, stems,
   media_jobs} → else `ARCHIVE_DB_INVALID`.
3. Rows are read with explicit column queries only; every record is
   validated through the application domain models (`ProjectRecord`,
   `AssetRecord`, `ImportRecord`, `MediaJob`, `AudioRepresentation`,
   `WaveformCacheRecord`, `MarkerRecord`, `SeparationRun`,
   `SeparationResultSet`, `StemRecord`). No SQL text from the archive is
   ever executed.

ID remap:

- Default `new-copy`: new `uuid4` project ID; every **project-local**
  row gets a new ID (imports, markers, project_history, separation_runs,
  separation_result_sets, stems, media_jobs, and the project row).
- **Assets are global content-addressed rows** (`assets.content_hash` is
  `UNIQUE`; `get_asset_by_hash` already reuses them on import): an asset
  whose content already exists in the store is reused by hash, not
  duplicated. `representations` (PK = `asset_id`) and `waveform_caches`
  (`asset_id` UNIQUE) are asset-global in the same way and are reused
  when the final asset already has a row. On-disk files stay deduped by
  hash.
- `as-archived`: allowed only when the archived project ID is absent from
  the store (else 409 `OPEN_ID_CONFLICT`); original IDs are kept.
- All FK references are remapped consistently: `project_id` (all
  project-scoped tables), `asset_id` (project_assets, representations
  including `parent_asset_id`, waveform_caches, stems'
  `audio_asset_id`, `projects.source_asset_id` / `canonical_asset_id` /
  `monitoring_asset_id`), `import_id` (media_jobs), `run_id` /
  `result_set_id` (separation_runs, separation_result_sets, stems),
  `stem_ids` + `bass_residual_asset_id` (result set),
  `projects.practice_state.active_result_set_id`.
- `record_json` blobs are remapped at the domain-object level (deserialize
  → remap ID fields → re-serialize via the repository), so embedded IDs are
  always consistent. Free-form JSON (`media_jobs.result` /
  `parameters`) gets a recursive exact-UUID-string replacement against the
  old→new map (the map only contains this archive's row IDs, so no
  collateral replacement is possible).
- Loop IDs inside `practice_state` are project-local (no other row
  references them) and are kept as-is.
- Provenance (§18.5): migration 11 adds `projects.portable_provenance TEXT`
  (nullable JSON): `{archived_project_id, saved_revision, saved_at,
  source_filename}`. `DATABASE_SCHEMA_VERSION` → 11; the v10 test
  baselines are updated the same way as for migration 10.

Asset file restoration:

- Destination per asset row:
  - `source_original` → `runtime/uploads/<new_import_id>.part` (new import
    ID, so the path is unique per working copy);
  - every other role → `data/assets/<content_hash><suffix>` (suffix from
    the row's `relative_path` basename; PCM assets are `.pcm`).
- Dedupe: destination exists and its SHA-256 equals the asset
  `content_hash` → reuse, skip copy. Destination exists with a different
  hash → `ARCHIVE_DB_INVALID` (collision; reject).
- Staged file missing (optional asset excluded at save time, e.g.
  playback-rate `derived_pcm`): drop the asset row and its dependent rows
  (representations, waveform_caches, project_assets) — the app regenerates
  on demand (§18.6). Essential assets can never be missing here (step 8).
- Waveform cache members (`caches/waveforms/<source_hash>/...`) → restored
  to `cache/waveforms/<source_hash>/...` with per-file hash verification
  and dedupe. Whole cache tree missing → drop the `waveform_caches` row
  (rebuild on demand).
- Provenance members (`provenance/*.json`) are verified but not stored
  (their data lives in the `separation_runs` rows; models are never part of
  the archive, §16.3).

Commit:

- All file restoration happens **before** the DB import; files are
  content-addressed and idempotent, so a mid-import failure leaves at most
  unreferenced files (harmless, dedupe-friendly).
- The DB import is a **single SQLite transaction** via a new
  `ProjectRepository.import_portable_bundle(bundle)` method: one
  connection, all remapped rows inserted (project row last inside the
  transaction), `PRAGMA foreign_key_check` must pass, then commit. The
  project is exposed (visible to `list_projects` / `get_project`) only
  after that commit (§18.4.8). Failure → rollback, staging deleted, session
  files kept (the user may retry with a fresh session).
- After commit: `archive_uploads.cancel_and_remove(session_id)` (success
  cleanup); the 201 response carries the new project ID.

§18.7 state restoration needs no extra work: the project row carries
`working_state` (viewport, selection, monitoring volume, last position),
`practice_state` (mixer, playback mode, speed, active result set, loops),
and the markers/result-set rows are imported — the frontend loads them
through the existing project-open snapshot path and opens paused.
Representations: canonical/downmix/stem files are present (essential);
playback-rate is regenerated by the existing on-demand job path when its
asset was absent.

### 6. Frontend

- `frontend/src/api/open.ts`: `createOpenSession(filename, byteCount)`,
  `uploadArchive(sessionId, file, onProgress, signal)` (reuses the
  `uploader.ts` chunk pattern), `completeOpenSession(sessionId)`,
  `cancelOpenSession(sessionId)`.
- `frontend/src/projects/OpenProjectPanel.tsx`: file picker
  (`accept=".basseparate"`) + drag-and-drop zone, upload progress, an
  "Opening…" phase during `complete` (synchronous server work), inline
  errors (including `OPEN_ID_CONFLICT` / `ARCHIVE_MEMBER_*` messages), and
  an `onOpened(projectId)` callback.
- Mounted in the project-list view (App.tsx) beside "New project" — the
  entry point on a clean install. `onOpened` refreshes the project list and
  navigates to the project-open view.
- CSS in `styles.css`; vitest for the API module (mock-fetch pattern) and
  the panel (picker, drop, progress, success → navigation, error states).

### 7. Tests

- Unit — validator: happy path on an M2.15-produced archive; bad zip;
  transfer cap; member cap; uncompressed cap; oversized/invalid manifest;
  wrong format/container version; absolute/traversal/duplicate/symlink/
  encrypted/directory/unknown member; missing essential; corrupted
  essential (hash + size); corrupted optional dropped; missing optional
  dropped.
- Unit — remap: all FK columns remapped; JSON-embedded IDs (run, result
  set, stem, practice_state) remapped; `as-archived` keeps IDs; provenance
  recorded; FK check passes.
- Integration — round trip: save project A (M2.15 pipeline) → open the
  archive into a **fresh store** → project ready; every asset file present
  with verified hash; markers/loops/result set/working state restored; new
  project ID; provenance set; a second open into the same store yields a
  second working copy (files deduped); `as-archived` succeeds when the ID
  is free and 409s when it is not; a damaged essential member rejects with
  the member named and leaves the store untouched.
- Integration — routes: session create (cap, filename, 507), chunks
  (offset mismatch, unknown session), complete (incomplete transfer,
  success, failure keeps session), cancel, GET state.
- Frontend: `open.test.ts` + `open-panel.test.tsx`.

## Invariants carried from M2.13–M2.15

- Export artifacts remain excluded from portable archives (unchanged).
- The portable DB is delete-journal, self-contained (unchanged).
- No telemetry; diagnostics local-only.
- Monitoring-only guarantee: opening never modifies the source archive;
  store writes are the new working copy's files + rows and deduped asset
  objects.
- Playback preparation priority over background work is unaffected (no
  jobs are dispatched by the open path).
