# M1.10 — Render the waveform editor (plan)

Spec: `projectPlans/milestone1.md` §12. Frontend package: the waveform
editor layout, canvas rendering pipeline, resolution selection, channel
and amplitude display, and the empty/pending states. Interactive
zoom/pan/selection is M1.11; the AudioWorklet transport is M1.12.

## 1. Scope boundary

In M1.10:
- Full §12.1 layout: header + source info (exist), transport (exists),
  overview waveform, main waveform, time ruler, marker lane (empty),
  selection readout (empty), horizontal scrollbar (static), channel
  display controls, vertical amplitude controls.
- §12.2 viewport model + transform — fit-to-song only
  (`start_frame = 0`, `frames_per_css_pixel = duration / width`);
  interactive changes are M1.11.
- §12.3 five canvas layers; playhead updates redraw only the playhead
  layer.
- §12.4 device-pixel-ratio handling with ResizeObserver.
- §12.5 resolution selection: peak level ≈ 1–2 buckets/CSS px, visible
  + 1 adjacent tile per side, obsolete-request cancellation,
  byte-bounded LRU, PCM switch below 64 frames/px with per-pixel
  aggregation, sample points/lines when frames are individually
  visible (fpp < 1).
- §12.6 channel lanes: mono 1 lane, stereo L/R, multichannel stacked
  labeled lanes; per-channel collapse; vertical virtualization (lanes
  outside the visible editor are not drawn).
- §12.7 amplitude: zero centered, default ±1, display scale 0.25×–16×
  with zoom in/out/reset controls labeled "Display amplitude";
  beyond-full-scale markers; playback gain untouched.
- §12.8 states: no source, decoding, waveform pending (progressive),
  missing/corrupt cache (rebuild button), valid silent audio (flat
  line, no special UI). "Unsupported input" stays in the import error
  path (M1.3).
- Playhead driven by the existing `PlaybackEngine` `onPosition`
  (project frames), lifted to the project view.

Not in M1.10: zoom/pan/selection interaction (§13), persistence of
display scale, AudioWorklet (§14), markers, looping.

## 4. Pure core (no DOM)

### viewport.ts
```
interface Viewport { startFrame: number; framesPerCssPixel: number; widthCssPx: number }
frameToX(v, frame) = (frame - startFrame) / framesPerCssPixel
xToFrame(v, x)     = startFrame + x * framesPerCssPixel
fitViewport(durationFrames, widthCssPx)  -> startFrame 0, fpp = duration/width
visibleRange(v)    = [startFrame, min(duration, start + width*fpp)]
```
Fractional coordinates throughout (spec §13.1.10, used by M1.11).

### levels.ts
```
chooseLevel(manifest, fpp)   smallest L with bucketFrameCount(L) >= fpp
                             (≈ 1 bucket/CSS px; one higher level when
                             the ratio would exceed 2 buckets/px)
tileRange(manifest, level, viewport) = [firstVisible, lastVisible]
adjacentRange(...)            = visible ± 1 tile per side (clamped)
pcmRange(viewport)            = [start, start + ceil(width*fpp)]
```
Level 0 bucket = 64 frames; `bucketFrameCount(L) = 64 * 4^L`.

### decode.ts (§11.5)
- `parsePeakTile(bytes, channelCount, expectedBuckets)` →
  `{ minima: Float32Array[], maxima: Float32Array[] }` (one per
  channel). Validates byte length (`buckets*channels*8`), rejects
  truncated bodies, reads f32le explicitly via DataView.
- `pcmChannelMinima(bytes, channelCount, framesPerPx)` → per-channel
  per-pixel min/max for the visible range (aggregation §12.5.6);
  complete frames only; rejects truncated bodies.
- `pcmSamples(bytes, channelCount)` → per-channel Float32Array for
  sample-level drawing (§12.5.7).
- The worker (`worker.ts`) is a 10-line wrapper posting
  `{ kind: 'tile' | 'pcm' }` jobs; decode.ts is what tests exercise.

### tileCache.ts
`class TileLru { maxBytes; get(key); set(key, bytes); }` — key =
`<hash>/<level>/<tile>`; evicts least-recently-used whole tiles;
`sizeBytes` bounded (default 32 MiB).

## 5. api/waveform.ts

- `getAssetMetadata(assetId)` → metadata incl. `waveform` (M1.9).
- `getPeaksManifest(assetId, signal)` → manifest JSON; 404 →
  `null` (state machine maps to pending/missing).
- `getPeakTile(assetId, level, tile, signal)` → ArrayBuffer
  (plain `fetch` with the session header, same as `fetchAssetBytes`).
- `getAssetPcm(assetId, startFrame, frameCount, signal)` →
  `{ bytes, startFrame, frameCount, eof, sampleRate, channelCount,
  contentHash }` from the M1.9 headers.
- 404/422 mapping: `NO_WAVEFORM_CACHE`, `TILE_NOT_READY` (retry),
  `PCM_RANGE_OUT_OF_BOUNDS`.

## 6. useWaveform.ts (data hook)

Inputs: `projectId`, `canonicalAssetId | null`.
Output: `{ state, manifest, levels: decoded tiles per level,
pcm: per-pixel or sample data, error }` where
`state = 'empty' | 'decoding' | 'pending' | 'missing' | 'ready'`.

Flow:
1. No canonical asset → `empty` (or `decoding` when the project has a
   completed import in flight — polled from the import list).
2. Fetch metadata; if `waveform` is present, fetch the manifest.
3. Manifest `final: false` → `pending`; poll every 500 ms visible /
   2 s hidden (`document.visibilityState`), redrawing as tiles appear.
4. No manifest and no live WAVEFORM job → `missing` (rebuild button
   posts a `waveform` job, then polls).
5. `final: true` → `ready`; for the current viewport (M1.10: fit-to-
   song) pick the level, fetch `adjacentRange` tiles through the LRU;
   if `fpp < 64` fetch PCM for `pcmRange` (bounded ≤ 8 MiB, chunked
   for longer ranges) and decode in the worker.
6. A viewport change (resize) increments a generation counter;
   in-flight tile/PCM fetches for the old generation are aborted
   (§12.5.3).

## 7. render.ts (pure draw functions)

All take `(ctx, ...)` in CSS pixels after the DPR transform; no
allocation-heavy work per frame.

- `drawLaneWaveform(ctx, lane, x0, width, opts)` — min/max fill per
  pixel from buckets (peak path) or per-pixel min/max (PCM path);
  zero line centered; amplitude scale applied; beyond-scale extrema
  marked (§12.7.4) with a clip tick at the lane edge.
- `drawSamplePoints(ctx, lane, ...)` — fpp < 1: points/lines per
  sample.
- `drawRuler(ctx, viewport, width, height)` — source-time ticks at a
  sensible interval for the current scale, no overlapping labels,
  ms shown when useful (§13.5 rules 1–4, static in M1.10).
- `drawPlayhead(ctx, x, height)` — one vertical line; the only
  function run on position updates.
- `drawGrid(ctx, ...)` — lane separators + zero lines.
- `drawOverview(ctx, manifest, width, height)` — coarsest-level mini
  lanes, one per visible channel.

## 8. WaveformEditor.tsx

Layout (top → bottom):
1. Source header row (rate, duration, channels — from source info).
2. Overview canvas (fit-to-song; viewport window = full width in M1.10).
3. Main view: ruler canvas + lane area + marker lane (empty, labeled)
   + selection readout (empty, "—") stacked; lane area is a
   fixed-height scrollable container (vertical virtualization: only
   lanes intersecting the container are mounted/drawn).
4. Per lane: five stacked canvases (waveform, grid, selection,
   markers, playhead) + channel label + collapse toggle.
5. Horizontal scrollbar row (static full-width thumb in M1.10).
6. Controls row: channel visibility checkboxes; "Display amplitude"
   group (zoom in / zoom out / reset; scale 0.25×–16×, default 1×).

DPR: each canvas measures its CSS box (ResizeObserver on the lane
row), sets `width = cssW * dpr`, `height = cssH * dpr`,
`ctx.setTransform(dpr, 0, 0, dpr, 0, 0)`; mouse/pointer math stays in
CSS px (§12.4).

State rendering (§12.8): `empty` → "No source imported.";
`decoding` → "Decoding audio…"; `pending` → progress + partial
waveform (available tiles drawn, rest blank); `missing` →
"Waveform unavailable." + "Build waveform" button; `ready` → normal
render. Silent audio renders as a flat center line (no special state).

Playhead: prop `playheadFrame` (project frames); an effect redraws
only the playhead canvases (`drawPlayhead`) — the waveform canvases
are untouched (§12.3).
